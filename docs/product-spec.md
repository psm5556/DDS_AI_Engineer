## 1. 제품 개요
### 1-1. 목적
사내 CAE 엔지니어가 **말로 요청하면 AI 에이전트가 CAD/CAE 툴을 다룬다.** 다음 과정을 이어서 처리하고 결과를 회사 자산으로 남긴다.
- 모델링 → 해석 → 결과 추출
- DOE → 예측 모델 → 최적화
- 3D Simulator → 보고서

PIDO 툴의 스크립트 작성과 프로세스 연결을 사람 대신 AI가 맡는다.

### 1-2. 사용자
| 사용자 | 하는 일 | 특성 |
|---|---|---|
| CAE 엔지니어(프로) | 요청·승인·결과 확인 | AI 전문가가 아님. 화면 문구는 쉬운 한국어로 쓴다 |
| 프로젝트 관리자(master) | 멤버 관리, 프로젝트 이름·삭제 | 프로젝트마다 정해진다 |
| 시스템 관리자(admin) | 사용자 승인, PC Agent 배포·모니터링 | 사내 서버 운영 |
| 공유받은 사람 | 배포된 Simulator로 예측만 | 프로젝트 멤버가 아니어도 된다(로그인 필요) |

### 1-3. 구성
```
[브라우저] ──HTTP/WS──> [사내 서버(Linux·Windows): FastAPI + React 빌드본 + SQLite, 포트 7014]
                             │ 학습·최적화·Simulator·보고서, 프로젝트·대화·결과·해석 데이터(case.h5) 저장
                             │ WebSocket /ws/agent (사용자 토큰)
                             ▼
                      [사용자 PC: PC Agent]
                             ├─ AI CLI(Claude Code·Gemini CLI·Codex)를 ACP로 구동 ── MCP 서버(dds-flow·cae·study·live)
                             ├─ CAD/CAE 툴 실행(스킬 스크립트) · 케이스 실행(로컬/HPC) · 결과·case.h5 업로드
                             └─ 프로젝트 작업 폴더(DDS_Workspace\P0001_…)
```
- AI CLI와 CAD/CAE 툴은 **사용자 PC**에서 돈다.
- 서버에는 숫자 결과·이미지·3D 필드·보고서·모델과 함께 대화 첨부 원본(1 GB 이하)·`case.h5`(500 MB 이하)도 올라간다. 그보다 큰 `case.h5`와 툴 산출물 원본은 PC에 남는다. 전체 목록은 `docs/local-data.md`.
- 표에서 시작하는 일(표 등록·학습·Simulator)은 서버에서 끝나 AI CLI와 PC Agent가 없어도 된다.
- 사용자마다 PC Agent는 1개만 연결된다(마지막 연결 우선).
- 인터넷 없는 사내망이 전제다. 외부 CDN·글꼴·패키지를 받지 않는다(사내 pip·npm 미러만 쓴다).

## 2. 디자인 명세
### 2-1. 원칙
1. **Claude·Codex 데스크톱 앱 방식**을 따른다.
   - 왼쪽은 사이드바, 가운데는 대화, 오른쪽은 캔버스다.
   - 단계(depth)는 최소로 한다.
   - 같은 기능의 버튼은 한 곳에만 둔다.
2. **결과는 캔버스, 대화는 짧게.**
   - 대화에는 사람이 읽을 요약(3~5줄)과 승인·확인 카드만 남긴다.
   - AI의 생각과 툴 호출은 "작업 N건" 한 줄로 접어 둔다.
3. **상태는 한 곳에서 보인다.**
   - PC Agent 연결 상태는 사이드바 아래에 둔다.
   - 작업 흐름 진행은 흐름도와 대화 카드에 보인다.
4. **오류에는 원인과 할 일을 함께 쓴다.** 예: "PC Agent가 연결되어 있지 않습니다 → 내 PC에서 DDS Agent를 실행하세요".
5. **문구**
   - 한국어로 짧게 쓴다. "무엇을 하면 무엇이 된다"가 보이게 한다.
   - 영어 약어는 처음 나올 때 풀어 쓴다(예: "R²(예측이 실제를 얼마나 잘 따르는지)").
   - 호칭은 "프로"를 쓴다. "경영진 보고" 같은 표현은 쓰지 않는다.
6. **데스크톱(1440×900) 기준.** 모바일은 깨지지 않는 정도만 맞춘다.
7. **색만으로 뜻을 전하지 않는다.** 기호(μ·σ·±)나 글자를 함께 쓴다.
   - 호박색은 확인이 필요한 일(승인 대기·경고)이다.
   - 주홍은 주 동작·선택·링크·진행이고, 청록은 AI·출력 값이다.
8. **무대와 작업대.**
   - 무대(로그인, 첫 화면, 빈 화면, 보고서 표지, Simulator 머리): 큰 글자, 3D·선 그래픽, 차례로 드러나는 등장(0.4~0.8초).
   - 작업대(대화, 작업 흐름, 표, 설정): 같은 재료를 쓰되 차분하게. 움직임은 상태가 바뀔 때만(0.12~0.24초).
   - 재료: 종이색 바탕, 잉크, 주홍 하나, 화면을 나누는 얇은 선, 고정폭 머리말·숫자.
9. **움직임 규칙.**
   - 기본 CSS가 최종 모습이고 `@keyframes`는 시작만 정한다. '움직임 줄이기'면 그대로 정지 화면이 된다.
   - 새로 생긴 것만 등장한다. 기록을 열거나 새로 고칠 때, 대화를 바꿀 때는 재생하지 않는다.
   - 투명도·위치 이동만 움직인다. 눌러야 하는 요소 자체는 끝없이 움직이지 않는다(고리는 `::after`에).
   - 일하는 화면에 넣지 않는 것: 표 행 등장, 값이 올라가는 숫자, Plotly 전환, 해석 3D 자동 회전·변형, 패널 폭 애니메이션, AI 답변 한 글자씩.
   - 어디에도 넣지 않는 것: 스크롤 가로채기, 커스텀 커서, 영상 배경, 닫힘 애니메이션, GSAP·Framer Motion·Lenis 같은 새 라이브러리.

**프로젝트 보기(사이드바)**: 프로젝트 목록 바로 위의 아이콘 4개로 고른다. 고르면 그 항목만 한 줄 평면 목록으로 보이고(최근 작업 순: 대화·작업 흐름·결과·스터디·이름 변경 중 가장 나중 시각, 위에 보기 이름), 프로젝트 검색은 고른 보기 안에서 찾는다. 아이콘 이름은 마우스를 올리거나 키보드로 왔을 때 글자 풍선으로 보이고, 아이콘 옆 숫자는 지금 검색어로 찾은 수다. 고른 보기는 브라우저에 기억하고, 처음에는 전체다.
- 지금 연 프로젝트가 고른 보기 밖이면 목록 위에 '지금 연 프로젝트'로 한 줄 따로 보인다. 방금 만든 프로젝트가 사라진 것처럼 보이지 않게 한다.
- 고른 보기 밖의 내 프로젝트(내가 멤버인 것)에 승인 대기나 실패가 있으면 전체 아이콘에 점을 찍는다.

| 보기 | 보이는 프로젝트 |
|---|---|
| 전체 | 내가 받는 모든 프로젝트. 즐겨찾기는 이름 옆 작은 별로 표시한다 |
| 즐겨찾기 | 내가 즐겨찾기한 것. 관리자가 멤버가 아닌 프로젝트를 즐겨찾기하면 그것도 여기 보인다 |
| 내가 공유한 것 | 내가 만들었고 다른 멤버가 있는 것. 내가 멤버에서 빠졌어도 만든 사람이면 여기 든다 |
| 공유 받은 것 | 내가 멤버이고 다른 사람이 만든 것. 관리자라서 보일 뿐 멤버가 아닌 프로젝트는 여기 들지 않는다 |

### 3-1. 로그인 (`/login`)

### 3-2. 첫 화면 (`/`, DashboardPage)
- 에이전트 기호, 큰 제목(`--fs-40`, 줄마다 등장), 설명 한 줄 아래에 **요청 입력창을 가운데** 둔다. 처음부터 입력창에 커서가 있다. 비어 있으면 예시 요청이 타이핑되고 입력을 시작하면 멈춘다(→ 키는 예시 전체를 받는다).
- 입력창 아래 **'옵션' 한 줄**에 프로젝트 이름·내 PC 작업 폴더를 접어 둔다("이름 자동 · 기본 작업 폴더"). 비워 두면 자동으로 정해지고, 폴더 오류가 나면 저절로 펼쳐진다.
- 그 아래 빠른 시작 5칸(선으로 나눔), **'이미 결과가 있다면' 두 칸**, 지원 툴 수 한 줄, 최근 프로젝트 줄(상자 없이, 올리면 화살표가 밀려 나옴)을 차례로 등장시킨다.
  - **표로 바로 Simulator:** 붙여넣기 창이 열린다. 입력창에 표를 바로 붙여 넣어도 된다. AI·PC Agent 없이 동작한다. 규칙은 3-6-1절.
  - **해석 폴더로 Simulator:** 입력창을 요청으로 채운다. 폴더 경로를 적어 보내면 에이전트가 케이스 결과를 모은다.
- 요청을 보내면 다음이 차례로 일어난다.
  1. 프로젝트가 자동으로 만들어진다. 이름은 요청 앞부분이고, AI가 첫 응답 때 짧은 이름으로 바꾼다.
  2. 작업 공간으로 이동한다.
- 첨부 파일은 프로젝트 작업 폴더 `inputs/`로 내려간다.
- PC Agent가 연결되지 않았으면 설치 안내를 먼저 보인다.

### 3-4. 작업 흐름 탭
```
┌ 제목 [완료]  목표 · 단계 7/7 완료 · 오늘 11:16     (흐름이 여럿이면 위에 고르기)
├ 진행 막대
├ 흐름도(고정, 높이 최대 40vh) — 작은 노드: [번호] 이름 [상태] / 종류 · 결과 n
├ "단계를 누르면 그 단계의 결과로 이동합니다 · 결과 N개"
└ 단계별 결과(이 부분만 스크롤)
   [1단계] 이름 [종류·툴] [상태]  (실패면 '원인 찾기')
   설명(detail)
   결과 카드들(표·그래프·이미지·요약) — 각 카드에 시각·삭제
   … 마지막에 [기타] 단계에 묶이지 않은 결과
```
- **단계 번호**는 `frontend/src/flow/order.ts`의 `orderNodes`로 매긴다. 엣지 기준 위상 정렬이고, 같은 순위는 원래 순서다.
  - 서버 `report.order_nodes`도 같은 규칙이다.
  - 이 번호를 흐름도·단계별 결과·대화 카드·보고서가 함께 쓴다.
- 흐름도 노드를 누르면 그 단계 섹션으로 부드럽게 스크롤한다. 선택한 단계는 번호를 주홍으로, 머리글 선도 주홍으로 표시한다.
- 노드 상태 색
  - 완료: 초록 체크
  - 진행: 주홍 고리가 퍼진다(맥박)
  - 실패: 빨강
  - 대기: 회색 점
  - 건너뜀: 흐리게
- 승인 대기 흐름에는 "대화의 카드에서 승인하거나 반려하세요"를 띄운다.
- 승인 대기·반려가 아닌 흐름에는 **[이 흐름을 새 모델로 다시]**를 하나 둔다. 누르면 입력창을 채우고 입력창 위에 [파일 고르기] 안내를 띄운다(바로 보내지 않는다). AI는 옛 스터디·모델·Simulator를 건드리지 않고 새 스터디로 진행한다(INSTRUCTIONS 1-2절). PC Agent가 없으면 이유와 할 일을 알린다.
- 흐름이 없어도 결과가 있으면 숨기지 않는다. 표에서 만든 Simulator·보고서처럼 흐름 없이 생긴 결과를 승인 규칙 안내 아래에 보인다.

### 3-5. 보고서 탭
- 보고서는 **AI가 작업 흐름·결과·스터디를 읽고 새로 쓴 문서**다. 결과를 모아 둔 것이 아니다.
- 머리글
  - 왼쪽: 작성 시각과 반영한 결과 수, 이전 판 고르기(판이 2개 이상일 때만)
  - 오른쪽: **[AI 보고서 작성]**(primary), Word | HTML
- 알림
  - 작성 중: "AI가 최신 결과로 보고서를 다시 쓰고 있습니다" + 탭 이름 옆 작은 회전 표시
  - 쓴 뒤 새 결과가 생기거나 바뀜: "새로 생기거나 바뀐 결과가 n개 있습니다 → 'AI 보고서 작성'으로 반영하세요"
- **보고서 틀**: 웹 탭·HTML·Word가 같은 틀을 쓴다. AI는 제목과 본문만 주고 틀은 코드가 붙이므로, 내용이 바뀌어도 틀은 지워지지 않는다. 결과를 모은 보고서(AI 보고서가 없을 때)도 같은 틀이다.
  - 표지: 로고 + DDS Conversa, 제목, 프로젝트 이름, 문서 번호(`DDS-P0012-R003`, 결과 모음은 `DDS-P0012-AUTO`), 판, 발행 일시, 작성자, "DDS Conversa 발행 · AI 작성, 담당 엔지니어 검토 필요"
  - 목차: 본문의 `##`·`###` 제목으로 만든다(코드 블록 안은 제외, 같은 제목도 각각 이동). 제목이 없으면 목차를 뺀다.
  - 맺음말: 발행처와 검토가 필요하다는 안내, 문서 번호·판·발행 일시
  - 웹 탭: 패널이 넓으면 왼쪽에 고정 목차와 현재 위치 표시, 좁으면 표지 아래 목록 + 패널 아래쪽 띠의 [목차로] 버튼(글 위에 뜨지 않는다). 패널 안에서만 스크롤한다(주소를 바꾸지 않는다). 고정 목차가 길면 현재 위치를 따라간다.
  - HTML: 파일 하나로 끝난다(파비콘·로고·그림이 파일 안에 있고 외부 요청 없음). 위아래 머리글·꼬리말, 왼쪽 고정 목차와 현재 위치 표시(스크립트가 없어도 이동은 된다), 좁은 화면과 인쇄에서는 목차가 일반 목록이 된다. 인쇄하면 쪽마다 로고·발행처·문서 번호·쪽 번호가 찍힌다(Edge·Chrome 기준. 쪽 여백 글자를 지원하지 않는 브라우저에서는 표지와 맺음말에만 보인다).
  - Word: 표지 다음에 누르면 이동하는 목차(책갈피 + 링크. 여는 순간 동작하고 "필드 업데이트" 질문이 뜨지 않으며, 쪽 번호는 넣지 않는다). 머리글에 로고·발행처·제목, 꼬리말에 문서 번호와 쪽 X / Y. 문서 속성의 작성자는 DDS Conversa다.
  - 종이에 찍은 목차에는 쪽 번호가 없다: Word·HTML 모두 쪽 번호는 넣지 않는다. 서버는 쪽 나눔을 알 수 없고, 틀린 번호보다 없는 편이 낫다. 화면에서 누르는 이동은 그대로 된다.
  - 넓은 표(인쇄·Word): 값이 잘리거나 숫자가 줄 중간에서 끊기면 안 된다. 세로 쪽에 안 들어가면 가로 쪽 + 작은 글자로, 그래도 넘치면 첫 열을 반복해 여러 표로 나눈다. 머리 줄은 쪽마다 다시 나온다. 화면의 HTML은 표 하나를 가로로 스크롤한다.
  - 그림(Word·인쇄): 원래 크기로 넣되 쪽 폭과 높이 200 mm를 넘지 않게 줄인다. 그림을 못 만들면 번호와 설명은 두고 그 자리에 "(그림 파일을 찾을 수 없습니다)" 같은 안내를 찍는다. 한 결과 때문에 문서 전체가 못 나가는 일은 없어야 한다.
  - 옛 판 본문: 앞의 `# 제목`과 직접 쓴 목차(목록만 있는 `## 목차`)는 틀과 겹치므로 빼고 보여 준다.
  - 로고·파비콘은 `frontend/public`이 원본이고 서버 사본 `server/app/assets/`를 쓴다(Linux 서버에 `frontend/public`이 없어도 되게, `test_server_assets_equal_frontend_public`이 어긋남을 막는다).
- 본문(문서 보기, 목차 제외 쪽 폭 최대 720px)
  - 마크다운(요약·목적과 조건·수행 내용·결과·결론과 권고·한계). 본문은 `##`부터 쓴다. 맨 앞에 제목과 같은 `#` 줄이 있으면 두 번 찍지 않는다.
  - 결과는 그림·표로 들어간다. 캡션에 **"그림 1." / "표 1."** 번호가 자동으로 붙고, "단계에서 보기" 링크가 있다
- 보고서가 없을 때: 빈 화면 설명과 [AI 보고서 작성]. 결과가 하나도 없으면 버튼이 꺼진다.
- 버튼을 누르면
  1. "최신 결과로 보고서를 다시 작성해 줘"가 대화로 전송된다.
  2. 새 판이 오거나 에이전트 차례가 끝나면 작성 중 표시를 거둔다(15분이 지나도 거둔다).

- 화면 표현: 표지(로고 + 큰 제목 + 발행 정보 + 잉크 선), 상자 없는 본문, 그림 번호는 고정폭 주홍. 새 판이 오면 표지부터 다시 등장한다. 파일의 색도 앱의 밝은 테마 토큰과 같고(`report.COLOR`·`PALETTE`), 그래프 계열 순서도 앱과 같다.

### 3-6. 데이터·모델 탭
스터디가 여럿이면 위에서 고른다. 위 줄의 **[행 추가]**는 이 스터디에 붙여 넣은 표의 행이나 새 출력 열을 더하고, 결과를 보여 준 뒤 다시 학습해 배포할지 묻는다. AI·PC Agent 없이 된다. 불러온 행은 케이스 표에서 지울 수 있다(잘못 넣은 값은 고쳐 넣어도 옛 행이 남으므로). 실행하던 PC와 끊겨 '실행 중'으로 남은 케이스가 있으면 이유를 띠로 보인다. 잠깐 끊긴 것이면 해석은 계속 돌고 다시 연결되면 결과가 들어온다. **[중지]**는 실행한 사람에게만 보인다. 구역은 위에서부터 다음 순서다.

1. **현재 최적**
   - 설계변수 값을 큰 숫자로, 목적값을 주홍으로 보인다. 목표가 여럿이면 "첫 번째 목표 기준"을 붙인다.
   - 케이스 진행 막대와 상태별 수, 실행 중·Output 추출 중 칩을 둔다.
   - 그 아래 "해석 데이터(HDF5) 68/68건 저장 · 서버 68건 2.8 MB · PC에만 n건" 줄이 있다.
1-1. **판단 도우미**(4-6-1절)
   - 맨 위 "지금 어디까지 왔나요?": 한 줄 사실과 다음 할 일 하나(버튼을 누르면 대화로 요청).
   - 그 아래 쉬운 질문 목록. **접혀 있어도 질문·상태·문장이 보인다.** 첫 줄만 읽어도 판단할 수 있어야 한다.
   - 줄을 누르면 그림과 "읽는 법"이 펼쳐진다. 그림은 펼칠 때만 그린다. 버튼은 구역당 하나다.
   - 출력이 여럿이면 위에서 고른다. 재계산 중에는 "새 결과로 계산 중" 칩이 뜬다.
   - 해석 전에는 설계 범위 질문만 보인다. 능동학습을 안 했거나 목표가 하나면 그 줄은 흐리게 낮춘다.
2. **입력·출력**(두 열)

   | 열 | 표시 | 내용 |
   |---|---|---|
   | 입력 · Input | 주홍 표시 | 변수 이름과 범위 |
   | 출력 · Output | 청록 표시 | 이름 · 역할(목적·최소/최대, 제약 ≤ 값) · 설명(단위) · 값이 있는 완료 케이스 수(n/전체, 모자라면 주황) |

   - **[+ Output 추가]**는 입력창을 "'스터디' 스터디에 Output 추가: "로 채운다. 사용자가 이름을 적어 보낸다.
3. **학습 데이터**: 4-9-1절. 완료 케이스가 4건 이상일 때 보인다. 표만 불러온 스터디에는 보이지 않는다(필드가 없어 만들 것이 없다).
4. **케이스 표**
   - 머리글은 두 줄이다(입력 묶음 주홍 / 출력 묶음 청록 + 항목 이름). 둘 다 고정된다.
   - 열: ID · 출처(DOE·최적화·능동학습·직접·불러옴) · 상태 · 입력들 · 출력들 · HDF5 · 폴더 열기
   - 출력 칸: 추출 중이면 작은 회전, 값이 없으면 빈칸
   - HDF5 칸: 서버에 있으면 크기 칩(눌러서 받기), PC에만 있으면 "PC · 크기"(위치는 툴팁), 오류면 빨강
   - 최적 행은 강조한다. 오류가 있으면 툴팁으로 보인다.
   - 불러온 케이스의 폴더는 작업 폴더 밖 원본이라 열 수 없다. 대신 경로 복사 버튼을 둔다.
   - 앞 200건만 그리고 [1,000건 더 보기]로 늘린다.
   - DOE 점이 있으면 머리글 오른쪽에 **[DOE 계획표 받기(CSV)]**. 대기 중인 점이 있으면 그 점만, 없으면 전부 받는다.

#### 3-6-1. 표로 바로 Simulator (`canvas/TableImport.tsx`)
회사의 CSV·엑셀 파일은 보안 프로그램으로 암호화되어 있어서 **표는 복사·붙여넣기로만 받는다.** 화면에 표 파일을 고르는 입구는 없다(대화 첨부는 CAD·입력 파일용으로 그대로 있다). AI·PC Agent 없이 끝까지 간다.

- **입구는 둘이다.**
  - 입력창(첫 화면·대화)에 표를 붙여 넣는다. 글자가 입력창에 들어가지 않고 입력창 안에 질문이 바로 뜬다. 탭으로 나뉜 칸이 둘 이상인 줄이 80% 이상이고 두 줄 이상이면 표로 본다.
  - [표로 바로 Simulator](첫 화면·데이터 탭·빈 Simulator 탭)가 여는 붙여넣기 창. 붙여 넣는 즉시 읽는다.
- **알아서 읽는다**(`POST /api/tables/preview/text`, 아무것도 저장하지 않음): 머리글·제목 줄, 이름, 단위, 숫자 열, 상수(고정값), 순번·글자 열(제외), 천 단위 쉼표, %, 빈 행·열, 따옴표 안 줄바꿈, 앞뒤 공백, 수식 오류(#N/A·#DIV/0!·####).
  - 병합 셀 빈칸은 출력이 아닌 열만 위 값으로 채운다(첫 칸에 값이 있고 빈칸이 4분의 1 이상인 열). 빈 출력은 채우지 않는다. 없는 결과를 지어내는 것이기 때문이다.
  - 머리글이 없으면 '열1, 열2…'로 붙인다.
- **묻는 것은 하나다: 어느 열이 결과(출력)인가.** 숫자 열 이름을 칩으로 보이고 추측을 미리 골라 둔다. 나머지 숫자 열은 입력이다. 최적화 목표는 묻지 않는다. 열마다 고르는 표나 다른 단계는 없다.
- **[인식한 내용 보기]:** 접혀 있다. 고정값, 뺀 열과 이유, 값 경고, 자릿수 경고(엑셀은 화면에 보이는 자릿수대로 복사한다).
- **[Simulator 만들기] 하나로** 표 등록 → 학습 → 배포 → Simulator 탭 열기까지 간다(`studies/import/text` → `train/start` 폴링 → `deploy`). 단계와 경과 시간을 보이고, 닫아도 서버에서 이어서 하며 끝나면 알린다.
  - 첫 화면은 이때 프로젝트를 만든다. 붙여 넣고 닫으면 프로젝트가 남지 않고, 등록이 거절되면 만든 프로젝트를 지운다.
  - 빠진 행이 있으면 끝날 때 알리고, 이유는 결과 카드 '불러온 데이터 확인'에 남는다.
  - 같은 표를 다시 붙여 넣으면 겹치지 않고 기존 스터디를 쓴다.
- **AI로 보낼 때:** 표를 붙여 넣은 채 요청을 적어 보내면 표를 첨부(`inputs/붙여넣은_표_시각.tsv`)로 서버에 저장한다. 행은 요청 글이나 도구 인자로 가지 않는다. AI도 출력 열만 묻는다(INSTRUCTIONS 0-2절).
- **한도:** 50 MB(`paste_max_mb`), 20만 행. 넘으면 "필요한 행과 열만 골라 다시 복사해 주세요".
- **입력과 출력이 다른 표에 있으면** 화면에서는 한 표로 합쳐 복사한다. 있는 스터디에 행을 더하는 일은 대화로 요청한다(`import_table(study_id)`).
- **암호화된 파일:** AI가 `import_table` 등으로 CSV·엑셀을 읽으려다 못 읽으면(엑셀인데 zip이 아님, 글자가 아닌 바이트) 깨진 표나 500 대신 "보안 프로그램으로 암호화되어 읽을 수 없습니다 → 엑셀에서 표를 복사해 붙여 넣으세요"로 답한다. `results.json`·`case.h5`·해석 폴더는 상관없다.

정확도가 낮아도 배포를 막지 않는다. 대신 Simulator 화면·공유 창·목록에 경고가 남는다(3-7절).

### 3-7. Simulator
**구조: Simulator는 스터디 하나이고, 모델은 그 버전이다.** 학습할 때마다 새 버전(v1, v2…)이 생기고, 현재 버전은 스터디마다 하나다.

| 어디서 | 주소 | 누구를 위한 것 |
|---|---|---|
| **Simulator 탭**(캔버스) | 프로젝트 안 | 작업하는 사람. 대화와 결과를 그대로 둔 채 예측하고 버전을 관리한다 |
| **Simulator 목록** | `/simulators`(사이드바) | 프로젝트에 들어가지 않고 바로 여는 사람. 내 것과 공유받은 것만 모은다 |
| **넓은 화면** | `/simulator/:mid`, 공유 `/s/:token` | 패널 없이 크게 보거나, 프로젝트 멤버가 아닌 사람이 볼 때 |

세 곳 모두 같은 화면(`SimulatorView`)을 쓴다.

- **넓은 화면에서 프로젝트로 돌아오기:** [프로젝트 열기]는 그 프로젝트를 열고 캔버스를 펼쳐 Simulator 탭의 같은 스터디·같은 버전을 보여 준다. 이동 정보는 주소 이력의 state로 넘기고 읽자마자 지운다. 새로고침이나 평범한 프로젝트 주소로 다시 오면 탭을 강제하지 않는다. 도착 직후에는 자동 따라가기가 탭을 바꾸지 않는다. 링크로 받은 사람에게는 이 버튼이 없다.
- **믿을 수 있는가(`components/ModelTrust.tsx`):** 슬라이더 위에 항상 보인다. 링크로 받은 사람도 같다.
  - 학습 데이터 출처: "불러온 표 120행" · "불러온 해석 결과 30건" · "해석 결과 40건". 링크로 받은 사람에게 파일 이름은 보이지 않는다.
  - 정확도 칩(좋음·보통·낮음)과 출력별 R² 칩. R²는 학습에 쓰지 않은 점으로 잰 교차검증 값이다.
  - 경고: 정확도·표본 수·제외 행·행 수 줄임을 원인과 할 일로 보인다.
  - 정확도가 낮으면 공유 링크를 만들 때 "받는 사람에게도 같은 경고가 보입니다"를 알리고, 목록에 [정확도 낮음]을 표시한다.
- **아직 모델이 없을 때:** 탭의 [예측 모델 학습]이 서버에서 바로 학습한다. PC Agent가 필요 없다. 학습 후 탭에서 배포한다.
- **믿어도 되는지 한 줄**(`TrustLine`): 화면 맨 위에 "이 예측을 믿어도 되나요? [보통] 진동 예측은 10번 중 8번 ±0.3 mm 안에서 맞습니다." 멤버 화면에는 글자 링크 [자세히]가 데이터 탭을 연다. 공유 화면에는 링크가 없고 프로젝트·케이스 정보도 내보내지 않는다.
- **예측**
  - 설계변수 슬라이더로 예측 결과를 바로 본다(평균 ± 표준편차). [가운데로]는 모든 변수를 범위 가운데로 돌린다.
  - 예측값은 크게(`--fs-40`, 고정폭, 탭 안에서는 `--fs-28`) 보인다. 값이 오래됐을 때만 흐려지고(`--dur-wait` 뒤), 늦게 온 옛 응답은 버린다.
  - 민감도: 한 변수만 바꿀 때의 변화 곡선. 주홍 점이 지금 설계다.
  - 형상·필드 모델이 있으면 3D 분포와 불확실도를 보인다.
  - 탭 안에서는 패널 폭이 820px보다 좁으면 한 줄로 쌓인다. 패널을 끌어 넓히면 두 줄이 된다.
- **입력이 많을 때(7개 이상):** 민감도 변수는 목록으로 고르고, 예측 결과를 슬라이더 위에 붙여 값을 바꾸며 함께 본다.
- **입력 범위는 그 버전을 학습한 범위다.** 행을 더해 스터디 범위가 넓어져도 다시 학습해 배포하기 전에는 슬라이더가 넓어지지 않는다. 숫자 칸에 범위 밖 값을 적으면 믿기 어렵다고 알린다.
- **버전(탭의 'vN · 버전 N개'를 눌러 편다)**
  - 표: 버전 · 출력별 R² 칩(0.9 이상 초록, 0.7 이상 주황, 그 밖 빨강) · 학습 수 · 만든 날.
  - 줄을 누르면 그 버전을 미리 본다. 미리 보는 동안 위에 안내와 [현재 버전으로](옛 버전이면 [이 버전으로 되돌리기])가 나온다. 이 버튼은 이 한 곳에만 있다.
  - 누르면 바로 적용된다. 다시 되돌릴 수 있는 일이라 확인을 묻지 않는다.
  - 현재 버전에 묶인 3D 모델: 배포할 때의 3D를 버전에 묶고, 배포 중에 다시 학습한 3D는 현재 버전에 붙는다. 되돌리면 3D도 그때 것으로 돌아간다.
- **공유**
  - 링크를 만들 때 기간과 메모를 정한다. 복사와 중지가 있다. 어느 버전에서 만든 링크든 같은 Simulator의 링크로 함께 관리한다.
  - **링크는 항상 현재 버전을 보여 준다.** 재학습·되돌리기를 해도 다시 보내지 않는다.
  - 공유받은 사람은 예측만 할 수 있고, 프로젝트 이름·대화·데이터는 보이지 않는다.
- **목록(`/simulators`)**
  - **내 Simulator:** 내가 학습한 모델의 Simulator.
  - **공유받은 Simulator:** 같은 프로젝트 멤버가 만든 것(프로젝트 이름과 함께), 링크로 받아 한 번 연 것(공유한 사람·메모와 함께). 같은 Simulator는 한 번만 보인다.
  - 공유가 중지되거나 기간이 끝나면 지우지 않고 흐리게 이유를 보인다. 왜 사라졌는지 알 수 있게 한다. 이때는 카드가 열리지 않고 모델 그림도 없다. [X]로 내 목록에서만 뺀다. 링크를 다시 열면 돌아온다.
  - **보기:** 기본은 그림 카드이고, 머리의 [카드]·[목록]으로 바꾼다(브라우저에 기억한다). 카드 어디를 눌러도 Simulator가 열린다. 카드에는 그림·이름(두 줄까지)·버전·출력(3개까지, 나머지는 +N)·프로젝트 또는 공유한 사람·수정 시각을 보인다. 목록의 출력 칸은 줄 폭의 36%까지만 쓰고(좁은 화면에서는 숨긴다) 이름 칸을 밀어내지 않는다.
  - **검색:** 입력하는 대로 이름·출력·프로젝트·공유한 사람·메모에서 찾는다(대소문자 구분 없음). 공유가 끊긴 것은 화면에 보이는 이름·공유한 사람·메모에서만 찾는다. 찾은 것이 없는 구획은 숨기고 구획 제목에 개수를 보인다. 찾은 것이 없으면 안내하고, 검색창의 X나 Esc로 지운다.
  - **카드 그림**(`GET /api/models/{m}/thumbnail`, 링크로 받은 것은 `GET /api/shares/{t}/thumbnail`). 순서대로 쓴다.
    1. 그 버전의 3D 모델: 설계 범위 가운데의 예측 형상·필드를 Simulator 3D의 첫 시점으로 서버에서 그린다(matplotlib, 투명 바탕, 큰 메쉬는 줄여서). 처음 요청할 때 한 번 그려 `data/thumbnails/`에 두고, 버전과 3D 모델이 바뀌면 새로 그린다. 되돌리면 그때 그림으로 돌아간다. 동시에 2개까지만 그린다.
    2. 프로젝트를 볼 수 있는 사람에게만: 그 스터디(제목이 `[스터디 이름]`으로 시작)의 이미지 결과, 없으면 그 스터디의 작업 흐름에 있는 이미지 결과 중 가장 최근 것. 링크로 받은 사람에게는 쓰지 않는다.
    3. 없거나 못 그리면(형상이 거의 보이지 않는 그림 포함) 서버는 204로 답하고, 화면은 Simulator 기호와 "설계변수 N개 · 출력 M개"를 보인다. 있지도 않은 3D나 결과를 그럴듯하게 그리지 않는다. 처음 그리는 동안에는 "그림 준비 중"을 보인다.
  - **그림 권한은 여는 권한과 같다.** 모델 주소는 프로젝트 멤버·관리자만, 링크 주소는 유효한 링크일 때만 받는다. 중지·기간 만료 링크는 404, 멤버가 아니면 403이다. 브라우저는 매번 서버에 확인하므로(`no-cache` + ETag) 권한이 끊기면 옛 그림도 받지 못한다.
  - 그림은 카드가 화면에 들어올 때만 받고 동시에 4개까지만 요청한다. 차례를 기다리다 화면을 벗어난 카드는 줄에서 빠지므로 지금 보이는 카드가 먼저 온다.
  - 받은 그림은 화면에 64장까지 보관해 보기 전환·검색·페이지 이동에 깜빡이지 않는다. 1분이 지나면 다시 그릴 때 뒤에서 서버에 확인하고(권한이 끊겼으면 지운다), 바뀐 때만 바꾼다. 처음 받은 그림만 나타나는 움직임을 쓴다.

### 3-8. CAD·CAE 툴 (`/tools`)
- 툴 29종을 분야별 앱 아이콘으로 보인다. 상태는 셋이다: 바로 사용 · 일부만 찾음 · 찾지 못함(흐리게).
- 툴을 누르면 서랍이 열린다: 할 수 있는 일, 내 PC 실행 파일, 실행 파일 고르기, 자동으로 되돌리기.
- [다시 찾기]로 내 PC를 다시 훑는다. "내 PC에 있는 것만" 필터가 있다.

### 3-9. 설정 (`/settings`)
구획마다 왼쪽에 제목·설명, 오른쪽에 내용을 두고 옅은 선으로 나눈다(상자를 쌓지 않는다).
- 내 PC Agent
  - 연결 상태와 버전을 보인다.
  - 자동 업데이트 선택(사용자마다 서버에 저장, 기본 켜짐). 켜 두면 대화·해석이 없고 마지막 작업에서 5분이 지났을 때 뒤에서 받아 두고, AI 도구가 떠 있으면 1시간 조용할 때 다시 시작한다(AI 도구가 없으면 5분). 끄면 기다리던 업데이트도 취소하고, '지금 업데이트' 버튼으로만 한다.
  - 설치: 설치 파일 받기, 또는 PowerShell 한 줄. 설치 파일은 웹앱과 같은 디자인의 4단계다(`installer/DdsAgentSetup.cs`).
    1. 계정 확인: 아이디·PIN으로 토큰을 자동 발급한다(이미 발급한 토큰도 쓸 수 있다). 이 PC가 이미 연결돼 있으면 묻지 않는다.
    2. AI 에이전트: Gemini·Claude·Codex가 이 PC에 있는지 먼저 확인한다. 있으면 선택을 막고 "설치됨". 본체만 있고 Agent가 실행하는 연결 구성요소(`claude-agent-acp`·`codex-acp`)가 없으면 그것만 설치한다.
    3. 설치: 진행 단계와 기록을 보여 준다.
    4. 로그인: CLI마다 [로그인] 버튼. 안내가 적힌 창을 열고, 사내 보안 환경의 긴 대기 동안 지난 시간을 계속 보여 준다. 로그인 정보 파일이 바뀌면 "로그인 완료"로 바뀐다.
  - 개발 AI 원격 시험 허용(관리자 계정만, 기본 꺼짐, 7일 뒤 자동으로 꺼짐, 최근 시험 표시). 규칙은 `docs/pc-verification.md`.
  - 토큰 발급·폐기. 토큰 원문은 발급할 때 한 번만 보인다.
- AI 에이전트: CLI별 설치·로그인 안내
- 내 PC 진단, 결과 뷰어 등록 상태, 로그인 PIN 바꾸기

## 4. 기능 명세
각 기능은 다음 순서로 쓴다: 무엇을 → 누가·어떻게 → 처리 → 결과·화면 → 코드.

### 4-1. 계정·권한
- **무엇을:** PIN 로그인(PBKDF2 해시), 가입 승인제, 5회 실패 잠금
- **처리**
  - API 토큰(사용자 PC Agent·MCP용)은 해시만 저장한다.
  - 프로젝트 권한은 master(관리)와 member(사용)다.
  - 다른 멤버의 PC에서 해석한 케이스 폴더는 열 수 없다.
- **코드:** `routers/auth.py` · `deps.py` · `routers/projects.py`

**프로젝트 멤버가 볼 수 있는 것과 할 수 있는 것.** 서버에 있는 것은 만든 사람의 PC가 꺼져 있어도 된다. 무엇이 서버에 있는지는 `docs/local-data.md`.

| 대상 | 멤버가 볼 수 있는가 | 멤버가 할 수 있는 일 | 만든 사람의 PC가 꺼져 있으면 |
|---|---|---|---|
| 작업 흐름·결과 카드·보고서 | 예 | 승인·반려, 결과 삭제, 내 PC Agent로 보고서 다시 쓰기 | 그대로 된다 |
| 다른 멤버의 대화 | 예(읽기 전용) | 보내면 **내** 새 대화로 시작한다. 그 대화의 AI 세션은 만든 사람의 PC에 있어 이어 쓰지 못한다 | 기록은 보인다 |
| 대화 첨부 원본 | 예, 내려받을 수 있다 | 내 대화에 첨부해 내 PC `inputs/`로 받는다 | 그대로 된다 |
| 케이스 입력·출력값, 이미지, 3D 필드 | 예 | 조회, 학습, 데이터셋 만들기 | 그대로 된다(필드·`case.h5`가 서버에 있는 케이스만 3D·데이터셋에 쓰인다) |
| `case.h5` | 서버에 있으면 내려받을 수 있다. PC에만 있으면 크기와 위치만 보인다 | - | 서버에 있는 것만 된다 |
| 예측 모델·Simulator | 예 | 학습(새 버전), 배포, 되돌리기, 공유 링크 만들기·중지, 표로 새 Simulator 만들기, 있는 스터디에 표의 행 더하기(대화로 요청) | 그대로 된다 |
| 스크립트 묶음(레시피) | 올렸으면 내려받을 수 있다 | 내 PC에서 이어 쓴다. **다른 사람이 쓴 스크립트라 실행 전 Flow 승인에 작성자를 보인다** | 그대로 된다 |
| 스터디 복제("신규 모델로 지난번처럼") | 예 | 설정을 복사한 새 스터디. 옛 결과는 바뀌지 않는다 | 그대로 된다 |
| 재해석·새 해석 | - | 내 PC Agent와 내 PC의 툴·스크립트로 실행한다. 스크립트가 없으면 묶음을 받아 쓰거나, 없으면 만든 사람에게 묶음을 올려 달라고 한다. 입력 모델은 첨부로 올라온 것만 받을 수 있다 | 된다(내 PC에서) |
| Output 추가(이미 해석한 케이스에서 뽑기) | - | **스터디 주인만** 한다(관리자 계정 포함 다른 사람은 403). 추출은 주인의 PC에서 돈다. 다른 멤버가 돌린 케이스는 그 PC에서 돌리지 않고 수를 알린다 | **안 된다.** 주인의 PC가 켜질 때까지 건너뛰고 이유를 알린다 |
| 해석 원본 파일(odb·d3plot 등), 케이스 폴더 | 아니요. 경로만 보인다 | 실행한 사람만 폴더를 연다 | 받을 수 없다 |
| 실행 중인 해석 | 상태가 보인다 | 내가 실행한 것만 중지한다(내 PC가 끊겨 있어도 된다. 다시 연결될 때 솔버를 끝낸다). 다른 멤버의 케이스는 중지·다시 돌리기 모두 403이고 "내 PC로 복사해서 하기"를 안내한다. 내 케이스가 이미 돌고 있으면 다시 시작하지 않고 그렇다고 알린다 | 잠깐 끊긴 것이면 솔버는 계속 돌고, 다시 연결되면 결과를 받는다 |
| 프로젝트 관리 | 예 | 이름·설명 바꾸기와 멤버 관리·삭제는 관리자(master)만 | 그대로 된다 |

**다른 사람의 작업은 보기 전용이다(사용자 결정).** 재학습·Simulator 배포·공유·보고서는 본인의 작업에서만 바로 한다. AI 지침(`agent-context/INSTRUCTIONS.md` 1-3절)은 이미 이 규칙을 따르고, 서버의 소유자 확인은 작업 구조와 함께 들어온다. 그때까지 위 표의 학습·배포 칸은 서버가 막지 않는 현재 동작이다.

**링크로 공유받은 사람**(멤버 아님)은 현재 버전의 Simulator로 예측만 한다. 데이터 출처 종류와 정확도·경고는 보이고, 프로젝트 이름·대화·데이터·파일 이름은 보이지 않는다.

### 4-2. 프로젝트·대화
- **처리**
  - 프로젝트: 만들기·이름 바꾸기·즐겨찾기·멤버·삭제
  - 대화: 프로젝트 안에 여러 개, 에이전트 바꾸기(이전 대화 요약을 넘겨 이어 감)
  - 첨부는 서버에 두었다가 PC Agent가 `inputs/`로 내려받는다.
  - 프로젝트 작업 폴더는 PC마다 다르다. 서버에 저장하지 않고 PC의 `index.json`에 둔다.
- **코드:** `routers/projects.py`·`sessions.py` · `agent/hub.py` · `agent/dds_agent/workspace.py`

### 4-3. 작업 흐름(Flow)
- **상태:** `review`(승인 대기) → `approved` → `in_progress` → `complete` | `failed` | `rejected`
- **처리**
  1. AI가 `propose_flow`로 단계(노드)와 연결(엣지)을 제안한다.
     - 노드 종류: cad·pre·solve·post·doe·train·optimize·deploy·task
     - 빠진 조건은 기본값을 정해 노드 detail에 적는다.
  2. 사용자가 승인하면 "진행하세요" 메시지가 간다.
  3. AI가 `update_node`로 단계 상태와 detail을 갱신한다.

### 4-6-1. 스터디 판단 도우미(Insights)
전문 지식이 없는 사람도 **첫 줄만 읽고 판단**하도록 쉬운 질문·그 질문의 답(상태 말)·숫자가 든 한 문장·다음 할 일을 먼저 보여 주고, 그림과 읽는 법은 펼칠 때만 보인다.

- **원칙**
  - 상태는 네 가지(`good`·`fair`·`caution`·`unknown`, 색도 넷)이고, 화면의 말은 **질문의 답**이다. '더 돌리면 좋아질까요? 좋음'은 거꾸로 읽히기 때문이다.

    | 항목 | good | fair | caution |
    |---|---|---|---|
    | `coverage` | 고르게 퍼짐 | 조금 부족 | 다시 잡기 권함 |
    | `quality` | 문제 없음 | 확인 필요 | 먼저 고치기 |
    | `influence`·`trust` | 믿을 만함 | 참고용 | 믿기 어려움 |
    | `convergence` | 거의 다 찾음 | 더 돌릴 만함 | 먼저 점검 |
    | `optimum` | 써도 됨 | 확인 후 사용 | 아직 쓰지 마세요 |
    | `pareto` | 함께 좋아짐 | 맞바꿔야 함 | 후보 없음 |
    | `active` | 효과 있음 | 효과 작음 | 효과 없음(오차가 늘면 '오차 늘어남') |

    `unknown`은 모두 '아직 판단 못 함'이다. 하고 싶으면 할 수 있는 일(목표 하나인 스터디의 두 목표 비교)은 '선택 사항'이고, 돌리지 않은 능동학습은 줄을 내지 않는다.
  - 자료가 모자라면 판정하지 않고 몇 건이 더 필요한지 말한다. 건수의 기준은 어디서나 최소 건수 max(8, 5×변수 수)다. 그보다 적으면 정확도·영향도·설계를 판정하지 않고, 다음 할 일도 학습이나 최적화가 아니라 해석 조건 추가다.
  - **해석으로 확인한 값**과 **예측값**을 항상 나눠 말한다(`basis`). 예측에는 "예측"을 붙인다.
  - **낱말:** 엔지니어에게 '모델'은 FE 모델이다. 대리 모델은 항상 '예측 모델'이나 'AI 예측'으로 쓴다. 'DOE'는 '처음 계획한 해석'이나 '해석 조건'으로 쓰고, 'AI가 고른'은 쓰지 않는다(최적화 점도 AI가 고른다).
  - 잴 수 없는 것은 재지 않았다고 말한다. 능동학습과 무작위의 비교는 사용자 스터디에 없다. '연습 함수 기준' 줄만 실제로 계산했을 때 따로 보인다.
  - 이미 있는 케이스와 모델로만 계산한다. **해석을 더 돌리지 않는다.**
- **항목**(코드 키 · 제목 · 판정 재료)

  | 키 | 제목 | 재료 |
  |---|---|---|
  | `coverage` | 설계 범위를 고르게 살폈나요? (공간 충진성) | 범위를 살핀 건수(처음 점 + 능동학습. 최적화 점은 세지 않음), 변수별 빈 구간, CD를 같은 크기 LHS·무작위와 비교, 거의 같은 점, 변수 상관, 남은 시간. 격자·요인 배치는 'N수준'이라고 말하고 수준 사이를 비었다고 하지 않는다 |
  | `quality` | 해석 결과에 이상한 값은 없나요? | 실패율, 실패가 몰린 구간(초기하 검정 × 비교한 구간 수), 튀는 값, 값이 모두 같은 출력(절대 크기가 아니라 값에 대한 비율), 제약 통과율 |
  | `influence` | 무엇이 결과를 좌우하나요? (영향도) | GP를 거친 Sobol 1차·전체 지수, 몫(T/ΣT), 방향(S/T가 작으면 '다른 변수 값에 따라'), 교호작용, 5겹으로 잰 순위 안정성, 주효과 곡선과 불확실 띠. 함께 움직인 변수는 나누지 않고, 해석이 없는 구간은 방향의 근거로 쓰지 않는다 |
  | `trust` | 이 예측을 믿어도 되나요? (예측 정확도) | 저장된 교차검증 예측을 **최적화 점을 빼고** 다시 채점한 R²·오차, "10번 중 8번 ±값"(|CV 오차| 80백분위), 최악 케이스, 모르는 곳, 돌리기 전 예측 대 결과, 모델 낡음. 거의 일정한 출력은 오차 크기로 판단한다 |
  | `convergence` | 더 돌리면 좋아질까요? (수렴성) | 제약을 만족한 해석값의 누적 최고, 처음 계획한 해석 대비 개선, 최근 W건 개선, 남은 여지(EI). 목표가 여럿이면 종합 점수(초부피)와 예측으로 본 남은 몫 |
  | `optimum` | 이 설계를 그대로 써도 되나요? | 가장 좋은 설계를 먼저 말하고, 앞 항목의 판단(예측 정확도·수렴·최적화 건수)을 이어받는다. 범위 끝, 제약 여유, 돌리기 전 예측, 예측 최선, ±2% 강건성(예측), 후보 표(해석 확인·예측 구분) |
  | `pareto` | 두 목표를 함께 좋게 할 수 있나요? (파레토 프론트) | 제약을 모두 만족한 해석값의 비지배 집합, 맞바꾸는 비율(기준 설계와 도착 값을 함께 말한다), 균형 설계(제안), 후보 표, 정확도가 충분할 때만 예측 후보(속 빈 점). 세 목표 이상은 후보 표와 고른 두 목표의 그림. 목표가 하나면 접어 두고 다른 출력을 골라 본다 |
  | `active` | 정확도를 높이려고 더 돌린 해석이 효과가 있었나요? (능동학습) | 학습 곡선, 점이 간 곳(한 번 더 눌러야 보임), 멈춤 조언. 불확실도 전후는 AI가 물으면 답하도록 facts에만 둔다. '아무 데나 골랐을 때와 비교하지 않았다'는 말은 첫 줄에 있다 |

- **학습 곡선의 방법:** 처음 점을 5겹으로 나눠 가리고, 나머지와 능동학습 점 앞 m건으로 학습해 가린 점을 채점한다. kernel은 최종 모델 값으로 고정한다(다시 최적화하면 점이 적을 때 값이 크게 흔들린다). **최적화 점은 곡선에서 뺀다.** 능동학습으로 고른 점의 효과만 재기 위해서다. 가린 점과 거의 같은 추가 점은 그 겹의 학습에서 뺀다(복사본이 정답을 알려 주면 정보 없는 추가가 개선으로 보인다).
- **능동학습 판정의 한계:** 가린 점은 처음 점이고 능동학습 점은 범위 끝으로 많이 간다. 그래서 곡선은 끝쪽 개선을 잘 보지 못한다(시험 함수: 실제 오차 47% 감소를 -2%로 잰 경우가 있다). 처음·능동학습 점을 합쳐 채점하는 방법도 재 보았으나 실제 감소와의 상관이 오히려 낮았다(0.88 → 0.51). 그래서 방법은 두고 말을 조심한다. 오차가 그대로면 '효과 작음'으로 두고 그 한계를 첫 줄에 쓰며, '효과 없음'은 오차가 10% 넘게 늘었을 때만 말한다. 멈춤 조언은 추가가 6건 이상일 때 최근 3건을 보고 말한다.
- **정확도의 범위:** 최적화 점은 한곳에 몰려 서로를 잘 맞히므로 R²를 부풀린다(Hartmann6 48+40점: 전체 R² 0.93, 실제 0.49, 최적화 점을 뺀 값 0.53). 판정은 뺀 값으로 하고 facts에 둘 다 남긴다. 점수에서만 빼고 학습에서는 빼지 않으며, 다시 맞추지 않으므로 빠르다. 모델 카드·학습 결과의 R²는 그대로 전체 값이다. 건수가 적으면 교차검증이 실제보다 나쁘게 나오므로(Branin 16건: CV R² -0.66, 실제 0.88) "학습에 안 쓴 점으로 맞춰 보니"라고 쓰고 그 사실을 펼침에 적는다.
- **두 목표 최적화:** 목적이 2개 이상이면 `optimize(mode="bo")`가 몬테카를로 Chebyshev EI × 제약 확률로 함께 좋아지는 쪽을 찾는다(`bayesopt.chebyshev_ei`). 케이스 출처는 그대로 `bo`다. '현재 최적'은 첫 번째 목표 기준이라고 표시한다.
- **요약 카드:** 건수는 '처음 계획 + 최적화 + 정확도 높이기'로 나눠 말한다. '바로 확정하기 전에 볼 것'에 주의·보통 항목을 3개까지 모아 누르면 그 항목이 펼쳐진다. 위쪽 초록 줄만 보고 끝났다고 여기지 않게 하기 위해서다.
- **다음 할 일:** 규칙표에서 처음 맞는 것 하나. 해석 조건 더 넣기(돌리기 전) → 실패 원인 → 연결 끊김·해석 중 → 건수 부족 → 대기 실행 → 학습 → 재학습 → 정확도 올리기(능동학습이 어렵다고 말했으면 원인 점검) → 최적화 → 더 돌리기 → 확인 해석 → 여유 찾기 → 범위 넓히기 → 배포·보고서 순서다. 모델이 필요한 항목을 아직 안 쟀으면 할 일을 말하지 않는다. 버튼은 입력을 대화로 보낸다. **하는 일이 같은 버튼(`action`)은 한 곳에만 둔다.** 'N건 더'에는 잰 시간이 3건 이상이고 1분 이상일 때 예상 시간을 붙인다.
- **이어받기:** 뒤 항목은 앞 항목의 판단을 따른다. 예측이 '믿기 어려움'이면 영향도·수렴·최적 설계도 확정처럼 말하지 않는다. 닫힌 줄의 상태는 목표·제약 출력 중 가장 낮은 것이고 그 이름을 함께 쓴다.
- **캐시:** 케이스 집계·스터디 버전·최신 모델 id로 만든 상태 키가 같으면 다시 계산하지 않는다. 모델이 필요한 계산은 백그라운드 데몬 스레드 1개에서 돌고 끝나면 `study_updated`를 보낸다. **스터디마다 최신 상태 하나만 기다린다**(낡은 계산은 줄에서 바뀐다). 그동안 `status: "computing"`과 빠른 항목(또는 직전 결과, `stale: true`)을 돌려주고, 낡은 결과의 다음 할 일은 내주지 않는다. 해석 중에는 빠른 항목만 5초에 한 번 다시 잰다. 빠른 층은 튀는 값을 재지 않으므로 '없다'고 말하지 않고 앞서 찾은 경고를 덮지 않는다. 결과는 `data_dir/insights/study_<id>.json`에 저장되어 재시작해도 남고 프로젝트를 지우면 함께 지운다. 저장 전에 스터디가 아직 그 스터디인지 확인하고(`owner`), 읽을 때도 맞춰 본다(SQLite는 id를 다시 쓴다). 일부 항목이 실패한 결과는 저장하지 않고 60초 뒤 다시 잰다. 옛 모델의 교차검증은 한 번만 재서 `cv_model_<id>.json`에 남긴다.
- **해석 중의 뜻:** `is_running`은 케이스 메시지로만 비워지므로 PC Agent가 끊기면 영영 참이다. 그 케이스를 돌리는 PC Agent 연결이 없으면(서버 mock 제외) 해석 중으로 보지 않고 '연결이 끊겼습니다'라고 말한다. 10분 동안 소식이 없어도 전체 판단을 한 번 계산한다.
- **AI·보고서:** `report-context`는 계산 중이면 합쳐서 20초까지 기다리고, 그래도 안 끝나면 낡은 문장 대신 `status: "computing"`과 `note`만 준다. `publish`는 30초 기다린 뒤에도 계산 중이면 409를 돌려준다. MCP `study_insights`도 계산 중이면 게시하지 않는다.
- **불러온 데이터:** `adapter == "data"`거나 출처가 `import`면 `basis`가 `imported`다. 문장과 그림의 "해석"을 "데이터"로 바꿔 쓰고 해석으로 확인했다고 말하지 않는다(앞으로 돌릴 '확인 해석'만 그대로 둔다).
- **돌리기 전:** 해석한 케이스가 없으면 `basis`가 `planned`다. 점을 계획했을 뿐이므로 "살폈습니다"나 "해석으로 확인한 값"이라고 쓰지 않는다.
- **'처음 계획한 해석'의 뜻:** 출처가 `bo`·`al`이 아닌 점이다. 수렴의 시작 값은 이 점에서만 고르고, 능동학습이 먼저 찾은 값은 최적화의 개선으로 세지 않는다. 이 점 중에 제약을 만족한 설계가 없으면 '없었다'고 따로 말한다.
- **수렴 규칙은 목표 수와 상관없이 같다:** 모델이 약하면(`caution`) 평평해 보여도 다 찾았다고 말하지 않는다. 처음보다 나아진 적이 없으면 '거의 다 찾음'이 되지 않고, 최적화 건수가 창의 2배 이상이면 '먼저 점검'이다.
- **멈춤 조언은 조건부다:** 남은 여지는 예측 모델의 짐작이고, 좁은 골짜기를 놓치면 자신 있게 틀린다. 그래서 '예측 모델이 보기에는'이라고 쓰고, 설계 범위 기준 정확도가 '믿을 만함'일 때만 '거의 다 찾음'이다. 아니면 '더 돌릴 만함'으로 둔다(Hartmann6·Ackley3의 잘못된 멈춤이 사라졌다). 모델이 전혀 보지 못한 좁은 우물은 이 규칙으로도 잡지 못한다(시험 함수로 확인). 그래서 문장을 확정처럼 쓰지 않는다.
- **목표가 여럿이면:** 값 대신 종합 점수(초부피)로 잰다. 짧게 평평한 것은 이 방법에서 흔하므로(외팔보: 10건에서 멈춘 듯했지만 35건 더 돌리니 그동안의 71%만큼 더 늘었다) 창의 2배 이상 돌렸고, 예측 앞면까지 합쳐 본 남은 몫이 2% 이하이고, 모든 목표의 예측이 '믿을 만함'일 때만 '거의 다 찾음'이다.
- **맞바꾸는 비율:** 기준 설계(균형 설계, 없으면 앞면 가운데)의 값과 도착 값을 함께 말한다. 기준값이 0에 가까우면(값 폭의 5% 미만) 퍼센트를 쓰지 않고 앞면 폭의 10%를 단위 값으로 말한다. 균형 설계가 첫 목표의 좋은 끝에 붙어 있으면 다른 목표 쪽으로 말한다. 부딪힘 판정의 분모는 사분위 폭이다(전체 폭은 이상한 값 하나에 흔들린다).
- **큰 표:** 거리 계산은 500점까지만 한다(`doe_stats`). 실패로 생긴 빈 구간은 정렬만으로 잰다.
- **Simulator:** 값 옆의 ±는 실제로 맞춰 본 오차(10번 중 8번)다. GP가 스스로 짐작한 폭은 훨씬 좁게 나오기도 해 툴팁으로 옮겼다. '자세히'는 데이터 탭을 열고 그 항목을 펼친다.
- **코드:** `study/insights_calc.py`(순수 계산) · `study/insights.py`(판단값·문장·판정·캐시) · `routers/insights.py` · `canvas/StudyInsights.tsx` · `components/TrustLine.tsx`

### 4-7. 입력·출력과 Output 추가
- **입력:** 설계변수(variables)
- **출력:** 목적 → 제약 → 추가한 출력(`Study.outputs [{name, note, post}]`) → 그 밖의 결과 키 순서로 보인다.
- **Output 추가**("OO도 Output에 넣어 줘") — `add_outputs(study_id, outputs, post?)`

  | 대상 | 처리 |
  |---|---|
  | 이미 해석한 케이스 | 해석은 다시 하지 않는다. 주인의 PC Agent에 `case.extract`를 보낸다. 케이스 폴더에서 추출 단계만 실행해 새 값을 기존 결과에 합친다. 스크립트 경로는 프로젝트 폴더 안의 상대 경로만 받는다(서버·PC Agent 둘 다 검사) |
  | 이후 케이스 | 추출 단계가 `adapter_config.post` 끝에 붙어 해석할 때 함께 돈다 |
  | 추가할 때 실행 중이던 케이스 | 끝나는 대로 빠진 Output만 추출한다 |

  - 스크립트 어댑터는 단계마다 쓴 `results.json` 값을 모은다. 그래서 추출 스크립트가 새 키만 써도 기존 값이 지워지지 않는다.
  - 실패하면 케이스는 complete로 두고 오류를 "Output 추출 실패: …"로 남긴다.
  - 해석한 PC가 연결되지 않은 케이스는 건너뛴다(건너뛴 수를 알려 준다).
  - mock은 해석함수를 다시 계산한다(`adapter_config.outputs`로 처음 남길 출력을 정한다).
- **코드:** `study/service.add_outputs`·`extract_outputs_async` · `cae_adapters/script.py`·`mock.py` `extract()` · skill-contract 1-2절

### 4-8. 해석 데이터 저장(HDF5, case.h5)
- **무엇을:** 케이스마다 결과를 **빠짐없이, 압축해서** 한 파일에 담는다.
  - 담는 것: 메타·메쉬·스텝별 전 프레임 필드·시간 이력·작은 텍스트·이미지
  - manifest: 케이스 폴더의 모든 파일을 packed·raw·skipped로 적는다. 원본은 크기·sha256을 남긴다.
- **언제:** 케이스가 끝날 때와 Output 추가 추출 후, PC Agent가 묶는다.
  - 묶은 뒤 다시 읽어 검증한다.
  - `upload_max_mb`(기본 500) 이하면 서버에 올리고, 넘으면 PC에만 두고 정보만 보낸다.

  - Output 추가: 그 케이스를 돌린 PC에서 원본이 지워졌으면 추출 스크립트가 케이스 폴더의 case.h5를 읽는다. 서버 사본으로 대신 뽑는 경로는 없다(3D 학습은 서버 사본으로 된다)

- **빠진 케이스:** 큰 `case.h5`가 PC에만 있으면 서버에서 읽을 수 없어 빠진다. 건수와 이유를 모델 정보(`info.excluded`)와 결과에 남긴다.

### 4-9-1. 학습 데이터(신경망 형상 학습용)
- **무엇을:** 케이스마다 `case.h5`에서 학습 샘플 `train.h5`를 뽑아 데이터셋으로 묶는다. 해석은 다시 하지 않는다.
- **입력 정보:** 묶을 때 입력 덱에서 재료·경계조건·하중을 뽑는다. 지금은 Abaqus `.inp`만 읽는다. 항목마다 `ok`·`none`·`not_extracted`를 남기고, 못 뽑은 입력은 학습에서 뺀다.
- **큰 케이스:** `case.h5`가 PC에만 있으면 그 PC Agent가 샘플만 만들어 올린다(`case.train_sample`).
- **화면:** 데이터·모델 탭의 '학습 데이터' 구역에 상태, 샘플 수와 분할, 출력·입력, 단위 모름, 빠진 입력, 제외된 케이스와 이유를 보인다.
- **코드:** `cae_adapters/deck.py` · `train_h5.py` · `meshops.py` · `study/dataset.py` · `routers/training.py`. 규약은 `docs/cae-data-hdf5.md` 8절.

### 4-10. Live Link(열린 CAD/CAE 조작)
- **무엇을:** 실행 중인 툴(NX 등)에서 바로 작업한다.
  - 치수 바꾸기 `live_set_params`, 화면 `live_view`, 되돌리기 `live_undo`
  - 그 밖의 일은 `live_exec`. 캡처는 `live_capture`

- **코드:** `mcp_servers/dds_live.py` · `agent-context/live/` · `.claude/skills/live-link-speedup`

### 4-11. PC Agent
- **설치·연결:** 설치 파일 또는 PowerShell 한 줄, 토큰으로 연결한다.
- **자동 업데이트:** 설정에서 켜 두면 서버에 새 버전이 배포될 때 유휴 시 뒤에서 업데이트한다. 유휴는 진행 중인 대화·케이스·CLI 설치가 없고 마지막 작업(`session.*`·`case.*` 등 사람이 시킨 메시지)에서 5분이 지난 때다. 받고 설치하는 동안 current.txt는 그대로이고, 그사이 시작한 일이 끝난 뒤에 전환하고 다시 시작한다. 다시 시작은 살아 있는 AI CLI를 끝내므로 CLI가 떠 있으면 `IDLE_RESTART_SEC`(1시간) 조용할 때까지 미루고, 서버에 전하지 못한 출력이 남아 있어도 미룬다. 뜬 뒤 마지막 CLI·대화를 미리 띄운다. 같은 버전은 한 번만 배포한다.
- **세션 유지:** 느린 CLI를 실패시키지 않고, 세션은 죽었거나 사용자가 끊었을 때만 버린다.
  - 요청은 저장하고 바로 돌아온다. CLI 준비는 뒤에서 한다. 진행 중이면 409. 시작 한계는 `cli_start_timeout_sec`(기본 1800초) 하나이고, 넘어도 프로세스를 끝내지 않으며 늦은 `initialize`도 받는다.
  - 끊겨도 턴·세션을 버리지 않는다. Agent는 대화 이벤트·턴 끝을 서버가 받았다고 답할 때까지 outbox에 쥐고 있다가 다시 보내고, 서버는 (boot, seq)로 중복을 거른다. 답을 못 받은 권한 요청도 다시 보낸다. 메시지 하나는 8MB를 넘지 않게 줄인다(큰 파일 diff·이미지가 연결을 끊지 않게).
  - DB가 잠겨도 메시지를 버리지 않는다. SQLite는 30초 기다리고, 서버는 2분까지 다시 시도한 뒤 넘어가며 빠진 출력은 턴 끝에 안내한다. 안내를 저장하지 못해도 턴은 끝낸다.
  - `hello`의 `live_sessions`·`active_turns`로 맞춘다. 살아 있는 세션은 `session/load` 없이 쓴다(Gemini는 load가 세션을 dispose한다). 서버를 다시 시작해도 턴을 되살린다. Agent가 다시 시작해 사라진 턴은 한 번만 안내하고 끝낸다. 서버와 Agent가 함께 다시 시작해 끝을 알 수 없게 된 턴은 답이 조금 나온 뒤였어도 대화별로 한 번 안내하고 끝나지 않은 도구를 닫는다.
  - CLI가 죽으면(`agent.runner_exit`) 그 세션을 잊고 진행 중 턴을 끝낸다. 다음 요청은 CLI 재시작 + `session/load`, CLI가 그 세션을 모른다고 하거나 load를 지원하지 않으면 새 세션 + 지난 대화 요약 + 안내 한 번. 일시적인 실패와 세션과 무관한 오류("model … not found" 등)로 세션을 버리지 않는다. 사용자가 중지한 요청은 요약에서 빼거나(CLI에 닿기 전) "중지한 요청"으로 표시한다.
  - 시작 중 중지는 바로 끝난다. 프롬프트는 보내지 않고 CLI는 끝내지 않는다. 그 뒤 작업 폴더나 에이전트를 바꾸면 늦게 끝난 세션을 대화에 묶지 않고, 새 CLI는 멈춘 CLI의 시작을 기다리지 않는다.
  - CLI를 끝내는 길은 "AI 도구 다시 시작"(`session.force_restart`) 하나다. 그 아래 멈춘 스크립트도 끝나고, 창이 보이는 CAD는 남는다. Agent가 받았다고 답하지 않으면(반쯤 끊긴 연결) 다시 연결될 때 보낸다. 곧바로 보낸 요청은 옛 CLI가 끝난 뒤 새 CLI로 간다. 0.2.16 이하의 Agent는 이 메시지를 모르므로 끝낸 척하지 않고 이유와 할 일을 알린다.
  - 옛 버전과 함께 쓰기: 0.2.16 이하의 Agent는 밀려나도 소켓을 닫지 않는다(곧바로 다시 붙어 서로 밀어내므로). 서버를 옛 버전으로 되돌려도 0.2.17 Agent는 응답 대기형 `session.prompt`에 답하고, `agent.settings`에 `acks`가 없으면 outbox를 쌓거나 다시 보내지 않는다.
  - 미리 띄우기: Agent가 뜨거나 재연결되면 `state.json`(agent.toml 옆)의 마지막 CLI를 `initialize`까지 띄우고 마지막 대화를 불러온다. 시작 시간도 여기에 재어 화면과 heartbeat에 보낸다. 끄려면 `warm_up = false`.
  - MCP 시간 제한: Claude Code는 `MCP_TIMEOUT`·`MCP_TOOL_TIMEOUT`을 준다. 제한을 바꿀 수 없는 Gemini(10분)·Codex(60초)는 `DDS_MCP_WAIT_LIMIT_SEC`로 긴 도구가 그 안에 돌아오게 하고 `script_status`·`get_study`로 이어서 확인한다.
- **스킬 동기화:** `agent-context`를 프로젝트 폴더로 복사한다. 내용이 그대로면(`.dds-context-stamp`) 건너뛴다. 세션마다 파일 수백 개를 복사하면 보안 검사에 걸린다.
- **그 밖:** 툴 자동 찾기(`toolscan`), 트레이 아이콘, HPC 실행(slurm·pbs 등)
- **코드:** `agent/dds_agent/*` · `installer/` · `scripts/install-agent.ps1`

### 4-12. AI 대화 정리 규칙(화면 쪽)
- 생각·툴 호출은 한 줄 묶음으로 접는다.

## 8. AI 에이전트 동작 규칙 (요약 — 원본 `agent-context/INSTRUCTIONS.md`)
1. **묻지 말고 진행한다.**
   - 빠진 조건은 기본값을 정해 Flow detail에 적는다.
   - 진행할 수 없을 때만 한 번에 모아 묻는다.
2. **대화는 3~5줄로 쓴다.**
   - 쓰는 것: 한 일, 핵심 숫자, 다음 권고
   - 쓰지 않는 것: 경로, id, 툴 이름, JSON, 진행 중계
3. **해석을 새로 돌리거나 사용자 모델을 바꾸는 일만 Flow를 제안하고 승인을 받는다.** 승인 뒤에는 단계마다 `update_node`를 부른다. 조회·후처리, 가진 데이터로 학습·Simulator 배포, 보고서는 승인 없이 바로 한다.
4. **결과는 캔버스에 게시한다.** `flow_id`·`node_id`를 넣는다.
5. **보고서는 해석해서 새로 쓴다**(INSTRUCTIONS 1-0절).
6. **Output을 더 원하면 `add_outputs`를 쓴다.** script 어댑터는 추출 스크립트를 한 케이스에서 먼저 시험한다.
7. **결과는 빠짐없이 남긴다.** 툴별 '결과 전체 저장' 단계를 `post`에 붙인다(case.h5).
8. **툴 스킬을 먼저 읽고 그대로 쓴다.** 새 스크립트는 1회 시험 실행으로 검증한다. 확인 안 된 API는 지어내지 않는다(`TODO(사내검증)`).
9. **결과는 `study_insights`의 상태 말과 문장으로 설명한다. `status`가 `ready`일 때만 인용한다.** 숫자를 새로 계산하거나 더 확실하게 바꾸지 않고, 예측값은 예측이라고 말한다. 능동학습이 무작위보다 나았다고 말하지 않고, 목표가 둘이면 한 설계를 답으로 정하지 않는다.

| Output 추가 | 이미 해석한 케이스 모두에 새 값(기존 값 유지), 이후 케이스에도 값, 표 열 순서 | `test_add_output_extracts_existing_and_later_cases`, `test_post_steps_merge_and_extract_existing` |
| HDF5 저장 | 케이스마다 case.h5, 검증 ok, manifest에 모든 파일, 서버 요약·받기, npz 없이 3D 학습 | `test_h5store.py`, `test_cae_to_h5.py`, `test_archive.py` |
| 대화 정리 | 생각·툴 호출이 한 줄로 접히고, 범위 표기(6~14)가 취소선이 되지 않는다 | 스모크 |
| 세션 유지 | 후속 요청·재연결·서버 재시작에 CLI 재시작 0회·`session/load` 0회. CLI가 죽으면 다음 요청이 재시작 + load로 이어지고, 끊긴 동안의 출력이 빠지거나 겹치지 않는다 | `test_sessions_stack.py`, `test_session_hub.py`, `test_session_keep.py`, `scripts/e2e_sessions.py` |
| 대기 표시 | 시작 중에도 POST가 바로 돌아오고, 단계·흐르는 시간·안내가 보이며, 새로고침해도 이어진다. 끊겨도 기록이 설치 안내로 바뀌지 않는다 | `scripts/e2e_sessions.py`(스크린샷) |
| 대화 움직임 | 기록을 열거나 새로 고쳐도 등장 움직임 없음, 새 항목만 등장. 턴 중 위로 올린 스크롤이 끌려 내려가지 않음 | 데모로 직접 |
| 규모 | 케이스 500행에서 표 스크롤·탭 전환이 끊기지 않음(이벤트 400ms 묶음, 표 줄 memo) | Playwright `page.route`로 부풀려 확인 |
| 판단 도우미 계산 | Ishigami·가산·곱 함수의 Sobol이 정답과 맞고, 비지배 집합·초부피·교환 비율·균형 후보가 손 계산과 같다. LHS는 '고르게 퍼짐', 몰린 점·같이 움직이는 변수·빈 구간은 '다시 잡기 권함'(변수와 구간 이름 포함). 무작위 실패는 몰렸다고 하지 않고, 최적화 점이 몰려도 정확도를 부풀리지 않으며, 무작위 최고점을 '써도 됨'이라고 하지 않는다. 수렴 문장이 손으로 만든 이력에 맞다. 자료가 모자라면 판정하지 않는다 | `test_insights_calc.py` |
| 판단 도우미 API | 멤버만 조회, 같은 상태면 다시 계산 안 함, 새 케이스 뒤 다시 계산, 해석을 돌리지 않음, 이상한 값(문자열·NaN·None·실패뿐)에도 500 없음, 공유 한 줄에 프로젝트·케이스 없음, 보고서 자료에 같은 문장, 계산 중이면 낡은 문장을 주지 않음, 줄에 스터디마다 최신 상태 하나, 지운 스터디의 결과가 다시 저장되거나 새 스터디로 보이지 않음 | `test_insights_api.py` |
| 문장 규칙 | 모든 틀에 전문 용어 금지어 없음, 첫 문장 90자 안쪽, 판단값 표가 코드와 같음 | `test_all_sentences_are_plain_and_short`, `test_thresholds_written_in_spec` |
| 판단 도우미 화면 | 데이터 탭에 질문 제목이 보이고, 접힌 채로 상태·문장이 읽히며, 펼치면 그림이 그려진다 | `npm run smoke -- --insights` |

### 10-3. 데모로 직접 확인(세탁기 시나리오)
1. `scripts\dev_live.cmd`(데모)를 띄운다.
2. 첫 화면에 "탈수 진동이 줄도록 스프링·댐퍼를 최적화해 줘. 탈수 1,200 rpm 기준, 현재 부품 범위 안에서 보고서까지 만들어 줘."를 보낸다.
3. 승인 → 허용 → 완료(1~2분)를 기다린다. 다음을 확인한다.
   - 작업 흐름 탭: 7단계, 결과
   - 보고서 탭: 그림 1~3, 표 1
   - 데이터 탭: 입력 4·출력 1, HDF5 68건
   - 데이터 탭: 판단 도우미의 질문이 모두 상태와 문장을 보인다
4. 데이터 탭 [Output 추가] → "바닥 전달력"을 보낸다. 출력 2개와 68/68을 확인한다.
5. 보고서 탭: '새 결과' 알림 → [AI 보고서 작성] → 새 판에 바닥 전달력 문장이 들어갔는지 확인한다.
