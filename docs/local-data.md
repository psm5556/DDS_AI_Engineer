# 사용자 PC 로컬 데이터 규칙

해석 원본·산출물(odb, d3plot, op2, sim 등 무거운 파일)은 **사용자 PC**에 남는다.
서버에는 숫자 결과, 메타데이터, 이미지·필드 요약, 그리고 "어느 PC의 어느 폴더인가"가 기록된다.
폴더 이름 앞의 번호(P/S/C + 서버 ID)가 서버와 로컬을 잇는 열쇠다. 이름 부분은 사람이 알아보기 위한 것이라 바뀌어도 번호로 찾는다.

```
%USERPROFILE%\DDS_Workspace\                (agent.toml의 workspace_dir)
  index.json                                내 PC 전체 프로젝트 색인 { "projects": { "12": {name, folder, server} }, "links": { uid: 직접 정한 폴더 } }
  P0012_브래킷-경량화\
    project.json                            프로젝트 ID·이름·서버 주소
    GEMINI.md / CLAUDE.md / AGENTS.md       에이전트 작업 규칙(자동 동기화, 탐색기에서 숨김. 아래 '규칙·스킬 파일 정리')
    .gemini/.claude/.agents\skills\         스킬(자동 동기화, 탐색기에서 숨김)
    .dds-skills.json / .dds-context-stamp   동기화 기록(탐색기에서 숨김)
    inputs\                                 대화 첨부·원본 모델 (수정 금지, 복사해서 사용)
    scripts\                                에이전트가 만든 자동화 스크립트
    runs\20261027_101500_<이름>\            단발 실행(dds-cae.run_script)
    studies\
      S003_두께-리브-DOE\
        study.json                          설계변수·목적·어댑터·툴 설정
        cases.csv                           전 케이스 한 표(ID·출처·상태·in:변수·out:결과·폴더) — 엑셀에서 바로 열림
        cases\
          C0001_doe\                        DOE 케이스
          C0021_bo\                         베이지안 최적화가 제안한 케이스
          C0031_al\                         능동학습이 제안한 케이스
            case.json                       케이스 메타(파라미터·결과·상태·시작/끝 시각·PC 이름)
            params.json  results.json  run.log  commands.json
            images\                         캡처 이미지 → 서버 결과로 업로드
            fields\<이름>.npz               3D 형상·필드(points, values, triangles) → 서버 업로드, 형상·필드 학습

    live\                                   Live Link 화면 캡처
    reports\                                보고서
```

## 프로젝트마다 작업 폴더 직접 정하기
기본은 위처럼 `workspace_dir` 아래 `P0012_…` 폴더이지만, 사용자는 프로젝트마다 내 PC의 아무 폴더(예: `D:\Work\브래킷_개선`)를 작업 폴더로 정할 수 있다.

- 정하는 곳: 첫 화면 입력창의 **기본 폴더** 버튼(새 작업을 시작하기 전), 프로젝트의 **파일** 탭 "폴더 바꾸기", 프로젝트 메뉴 "작업 폴더 바꾸기".
  **찾아보기…**를 누르면 PC Agent가 내 PC에 Windows 폴더 선택 창을 띄운다. 경로를 붙여 넣어도 된다.
- 기록: 이 PC의 `index.json` → `"links": { "<프로젝트 uid>": "D:\\Work\\브래킷_개선" }`. 폴더는 **사람마다·PC마다** 다르다(서버에 저장하지 않음).
  멤버는 각자 자기 PC에서 정한다.
- 정한 폴더 안에도 위와 같은 구조(project.json·inputs·scripts·runs·studies·reports, 에이전트 규칙 파일)를 만든다.
  기존 파일은 옮기거나 지우지 않는다. 사용자의 CLAUDE.md·AGENTS.md·GEMINI.md에는 표시한 구간만 덧붙이고(아래 '규칙·스킬 파일 정리'), `project.json`이 이미 있으면 프로젝트 정보 항목을 더해 다시 쓴다.
  사용자 스킬 중 DDS 스킬과 이름이 같은 폴더에는 DDS 스킬 파일을 덮어쓴다.
- 쓸 수 없는 폴더: 드라이브 최상위(`C:\`), Windows·Program Files·ProgramData 아래, 다른 프로젝트가 쓰는 폴더(그 폴더의 project.json uid가 다름).
- 바꾸면 이미 만든 파일은 옮기지 않는다(이전 폴더에 남음). 숨긴 DDS 규칙·스킬과 사용자 규칙 파일의 DDS 구간도 그대로 남고, 지우는 기능은 없다. 그 폴더에서 CLI를 직접 쓰면 이 규칙을 계속 읽을 수 있다. 에이전트 CLI 세션은 시작 폴더가 고정이라, 내 대화는 다음 요청부터
  새 폴더에서 새 세션으로 이어 가고 지난 대화 요약을 함께 넘긴다. 에이전트가 작업 중이거나 이 PC에서 케이스를 실행 중이면 바꿀 수 없다.
- "기본 위치 사용"을 누르면 원래 `P0012_…` 폴더로 돌아간다.

## 규칙·스킬 파일 정리
사용자 폴더가 지저분해지지 않게 DDS가 만든 파일을 눈에 띄지 않게 둔다. 깔끔하게 하려는 것이지 **보호 수단이 아니다**(탐색기에서 "숨긴 항목"을 켜면 보인다). 코드는 `agent/dds_agent/context.py`.

- **숨기는 것(Windows Hidden 속성):** DDS만 만든 규칙 파일, 동기화 기록, `.claude`·`.gemini`·`.agents` 폴더. 동기화를 건너뛰는 때에도 맞춘다(파일 내용을 읽지 않고 이름·크기만 본다).
- **숨기지 않는 것:** 사용자 글이 들어 있는 규칙 파일, 다른 내용이 든 `.claude` 등의 폴더(그 안에서는 DDS 스킬 폴더만 숨긴다). 나중에 사용자가 그런 내용을 넣으면 DDS가 숨겼던 것을 다시 보이게 한다. 사용자가 직접 숨긴 것은 건드리지 않는다.
- **사용자 규칙 파일:** 표시한 구간(`DDS Conversa 규칙 시작`~`끝`)만 넣고 고친다. 구간 밖의 글은 바이트 그대로 남는다(인코딩·줄바꿈 포함). 기존 파일은 제자리에서 고쳐 권한(ACL)·하드 링크·이름의 대소문자도 그대로다. 구간을 지우면 다음 동기화 때 다시 들어간다.
  - 이 파일이 git에 올라가 있으면 **구간이 변경으로 보인다.** 팀이 같은 파일을 바꾸면 `git pull`이 멈추고, 구간에 이 PC의 절대 경로가 들어 있어 커밋하면 그 경로도 함께 올라간다.
- **지난 버전이 통째로 쓴 규칙 파일:** 처음 동기화할 때 옛 규칙과 스킬 목록을 빼고 구간 하나로 바꾼다. 제목 앞이나 스킬 목록 뒤에 덧붙인 글은 남기고, 그 글이 있으면 파일을 숨기지 않는다. 옛 규칙 본문 안을 직접 고친 내용은 사라진다(지난 버전도 업데이트 때마다 덮어썼다). 이미 덮어써진 사용자 파일은 되살리지 못한다.
- **웹 파일 탭:** 숨긴 항목을 목록에서 뺀다. 사용자 파일은 그대로 보인다.
- **git 저장소인 폴더(또는 그 안쪽 폴더):** 숨긴 항목을 `.git/info/exclude`에 프로젝트 경로별 구간으로 적어, 한 저장소의 프로젝트들이 서로의 항목을 지우지 않는다. `.gitignore`와 이미 추적 중인 파일은 건드리지 않으며, 저장소가 아니면 조용히 넘어가고 실패하면 다음 세션에 다시 시도한다. 저장소를 다시 만들었는지는 제외 목록과 `.geminiignore`의 크기로 알아챈다.
- **`.geminiignore`:** Gemini의 `read_file`이 exclude에 든 경로를 거부한다. 그래서 작업 폴더가 저장소 최상위이면 이 파일에 표시한 구간을 넣어 스킬 폴더를 다시 연다. DDS만 만들었으면 숨기고, 사용자 파일이면 보이게 둔다.
  - 이 파일이 git에 올라가 있거나 git이 실패해 올라갔는지 알 수 없으면 **고치지 않고 숨기지도 않는다.** 그때는 스킬 폴더를 exclude에 넣지 않아 **스킬 폴더가 git에 새 파일로 보인다.** `git add -A`로 올라갈 수 있지만, Gemini가 스킬을 못 읽는 쪽보다 낫다고 보았다.
- **Hidden 속성의 부작용:** PowerShell `Get-ChildItem`은 `-Force` 없이 이 항목을 보여 주지 않고, Node `fs.writeFileSync`·cmd `>`·`Out-File`은 숨긴 규칙 파일에 쓰지 못한다. 경로를 지정해 읽는 것은 된다. 규칙 파일의 스킬 목록 앞에 AI가 볼 안내를 적어 둔다.

CLI가 숨긴 파일을 찾는지 실제 프로그램으로 확인한 결과(2026-10-31, Windows 11).

| CLI | 규칙 파일 | 스킬 | 확인 방법 |
|---|---|---|---|
| Claude Code 2.1.316 | 읽음 | `alpha`·`beta` 모두 보임, Read·Glob 됨 | `claude -p` 2회 비교(보임 / 숨김+exclude). 표시 구간이 든 파일과 ACP가 쓰는 번들 2.1.310은 돌려 보지 않음 |
| Codex 0.165·0.166 | 읽음(기본 32KiB에서 잘려 PC Agent가 `project_doc_max_bytes`를 늘림) | 보임 | `codex debug prompt-input`을 저장소 안팎 6가지 배치에서 실행. codex-acp를 거쳐 설정이 전달되는지는 돌려 보지 않음 |
| Gemini CLI 0.65 | 읽음 | 보임(신뢰한 폴더만. 숨김과 무관) | `gemini skills list`와 파일 필터 `shouldIgnoreFile`을 같은 6가지 배치에서 실행. 대화 턴은 돌려 보지 않음 |

저장소 최상위에서는 Gemini의 `read_file` 필터가 `GEMINI.md`·`AGENTS.md`를 거부한다(exclude에 들어 있어서). 규칙 파일은 메모리로 읽으므로 스킬과 달리 다시 열지 않았다.

ripgrep은 Hidden 속성을 숨김으로 다뤄 `--hidden` 없이는 건너뛴다. Claude Code의 Grep은 `--hidden`을 쓰지만 exclude에 든 경로는 찾지 못하고, Read·Glob·스킬에는 영향이 없다.

## 연결과 조회
| 하고 싶은 일 | 방법 |
|---|---|
| 웹에서 내 PC 폴더 보기 | 캔버스 **파일** 탭 (PC Agent가 목록을 보내 줌, DDS 규칙·스킬 파일은 뺀다). 위쪽에 실제 경로와 "기본 위치/직접 지정"이 보인다 |
| 탐색기로 열기 | 파일 탭·케이스 표의 📂 버튼, 프로젝트 메뉴의 "내 PC 작업 폴더 열기" |
| CAE 뷰어로 열기 | 파일 탭의 👁 버튼 → `agent.toml [viewers]`의 확장자별 명령 (없으면 Windows 기본 프로그램) |
| 다른 멤버의 케이스 | 그 멤버의 PC에 있다(케이스 표에 실행한 사람 표시). 숫자 결과·이미지·필드는 서버에서 모두 볼 수 있다 |
| 엑셀로 정리 | `cases.csv`(UTF-8 BOM) 또는 캔버스 표의 복사 버튼 |

## 원칙
- 원본(inputs)은 읽기 전용이다. 케이스는 원본을 복사해서 실행한다.
- 케이스 폴더는 지우지 않는다. 실패한 케이스도 `run.log`와 함께 남겨 원인을 추적한다.
- 프로젝트를 웹에서 삭제해도 로컬 폴더는 지우지 않는다. 정리는 사용자가 직접 한다.
- 경로 길이(260자) 때문에 폴더 이름은 짧게(최대 24자) 만든다. `workspace_dir`도 짧은 경로를 권장한다(예: `D:\DDS`).
