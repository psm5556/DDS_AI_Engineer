# 사용자 PC 로컬 데이터 규칙

해석 원본·산출물(odb, d3plot, op2, sim 등 무거운 파일)은 **사용자 PC**에 남는다.
폴더 이름 앞의 번호(P/S/C + 서버 ID)가 서버와 로컬을 잇는 열쇠다. 이름 부분은 사람이 알아보기 위한 것이라 바뀌어도 번호로 찾는다.

## 무엇이 서버에 올라가는가
프로젝트 멤버는 서버에 있는 것을 볼 수 있다. 무엇을 할 수 있는지는 [product-spec.md 4-1절](product-spec.md) 표에 있다.

| 올라가는 것 | 자세히 | 크기 제한 |
|---|---|---|
| 대화 | 요청·답변·도구 입출력 요약 | - |
| 대화 첨부 **원본 파일** | CAD·입력 파일을 그대로 서버에 저장한 뒤 PC Agent가 `inputs/`로 내려받는다. 멤버가 받을 수 있다 | 파일당 1024 MB(`max_upload_mb`) |
| 케이스 숫자 | 입력값, 출력값, 상태, 폴더 경로(`run_dir`) | - |
| 붙여 넣은 표의 값 | 표의 숫자를 케이스로 저장한다. 붙여 넣은 글 자체는 저장하지 않는다. 표를 AI에게 보내면 그때만 첨부(`붙여넣은_표_시각.tsv`)로 저장된다 | 50 MB(`paste_max_mb`) |
| 해석 데이터 `case.h5` | 메타·결과·필드 전 프레임·이력·로그를 담은 HDF5. 이 크기 이하면 서버에도 올린다 | 기본 500 MB(`upload_max_mb`, 넘으면 PC에만 두고 정보만 보낸다) |
| 3D 필드 | 케이스별 `fields/*.npz` | 파일당 200 MB |
| 학습 샘플 | 데이터셋을 만들 때 케이스별 `train.h5` | [cae-data-hdf5.md](cae-data-hdf5.md) 8절 |
| 이미지·결과 카드·보고서 | 캡처 이미지(케이스당 6장), 표·그래프, 보고서 | - |
| 예측 모델 | 학습은 서버에서 하므로 모델 파일도 서버에 있다 | - |
| 스크립트 묶음(레시피) | 사용자가 올린 경우에만. 다른 멤버 PC에서 내려받아 쓴다. 서버는 검사와 보관만 하고 실행하지 않는다 | 묶음 20 MB, 파일당 5 MB, 200개 |

서버에 올라가지 않는 것: 500 MB가 넘는 `case.h5`, 툴 산출물 원본(odb, d3plot, op2, sim 등), 스크립트(묶음을 올리지 않았을 때), PC별 작업 폴더 위치(`index.json`).

## 폴더 이름
기본 위치의 프로젝트 폴더는 항상 `P0012_<이름>`이다. 번호만 있는 폴더는 만들지 않고, 이름을 모르면 `P0012_untitled`로 시작해 이름을 알게 되면 바꾼다. 코드는 `agent/dds_agent/workspace.py` `sync_name`.

**이름을 바꾸면 무슨 일이 일어나나**

| 상황 | 탐색기에 보이는 것 | 실제 폴더 | 언제까지 |
|---|---|---|---|
| 이 프로젝트에 살아 있는 세션·실행 중인 케이스가 없다 | 새 이름 | 바로 바뀐다 | 끝 |
| AI 세션이 살아 있거나 케이스가 돈다 | 새 이름(접합) | 옛 이름 그대로, 숨김 | 세션이 끝난 뒤 첫 안전한 때 |
| 접합을 만들 수 없다(네트워크·FAT 드라이브, 회사 정책), 또는 대소문자만 다르다 | 옛 이름 | 옛 이름 그대로 | 같음. 파일 탭에 "폴더 이름은 지금 작업이 끝난 뒤 …(으)로 바뀝니다"를 보여 준다 |

**왜 세션이 살아 있으면 못 바꾸나:** Windows는 프로세스가 cwd를 둔 폴더, 그 안의 파일을 연 폴더의 이름을 바꾸지 못한다(WinError 32·5, 공유 모드와 무관, 측정). Claude Code는 세션마다 `claude.exe`와 MCP 서버의 cwd를 이 폴더에 두고 세션이 끝날 때까지 놓지 않는다. 회사 PC에서 CLI 시작은 몇 분이 걸려 세션을 끄지 않으므로, **세션이 며칠 살아 있으면 그동안 실제 폴더 이름은 옛 이름이다.** 사람에게는 접합 덕분에 새 이름만 보인다. Codex·Gemini는 잠그지 않을 수도 있지만 cwd를 메모리에 두어, 이름을 바꾸면 그 세션이 끊긴다. 그래서 rename이 성공하는지가 아니라 "살아 있는 세션·해석이 없는가"로 판단한다.

**실제 이름을 바꾸는 때:** 그 프로젝트에 세션이 없고 PC의 케이스 실행·원격 시험이 쉴 때만, 다음 시점에 시도한다: 서버가 이름을 알려 줄 때, CLI가 뜨기 직전, 턴 끝, CLI 종료 뒤(2초·20초 뒤), Agent 시작(미리 띄우기 전), Agent 종료, 5분마다. 다른 프로그램(CAD·뷰어·남은 솔버)이 잡고 있으면 시도만 실패하고 다음에 또 한다. **세션·솔버·CAD를 끝내지 않는다.** 먼저 임시 이름 `P0012_dds-moving`으로 옮겨 잠금을 확인하므로, 실패해도 보이는 이름은 끊기지 않는다. 도중에 Agent가 죽어도 번호로 다시 찾아 마무리한다. 기다리는 상태는 `project.json`·`index.json`에 남아 Agent를 다시 시작해도 이어 간다.

**옛 이름:** 실제 이름을 바꾸면 옛 이름마다 숨긴 접합을 남긴다(최근 8개). AI 스크립트·CAD 파일·서버의 `Case.run_dir`에 적힌 옛 절대 경로가 그대로 돌게 하기 위해서다. 이름을 또 바꿔도 다시 연결한다. 숨긴 항목을 켜면 보이고, 지워도 대상 폴더는 안전하다. 8개를 넘은 것과 실제 폴더가 사라져 끊긴 것은 지운다. Linux·macOS에는 Hidden 속성이 없어 옛 이름 링크가 목록에 그대로 보인다.

옛 이름은 바꾸는 순간 수 밀리초 동안 비어 있다. 그 사이에 Agent 밖의 프로그램이 옛 절대 경로로 `makedirs`를 하면 진짜 폴더가 생긴다. `stray_names`에 적어 두었다가 번호 폴더와 같은 규칙으로 합친다(덮어쓰지 않고, 파일 탭에 알린다).

**프로세스가 끊겼을 때:** 작업 공간을 고칠 때는 `.dds-lock`(숨김)을 OS 잠금으로 잡는다. Agent와 MCP는 다른 프로세스이기 때문이다. 프로세스가 죽으면 저절로 풀린다. 실제 이름을 바꾸기 직전에 `moving`을 `project.json`에 적어, 바꾼 직후 죽어도 사람이 바꾼 이름과 구별해 뒷정리를 마친다. 실제 폴더를 숨기기 전에 `hid_real`을 먼저 적어, 기록 없이 숨겨진 폴더가 생기지 않는다. `index.json`·`project.json`을 읽지 못하면(잠김) 잠깐 기다리고, 그래도 안 되면 그 작업을 멈춘다. 빈 기록으로 보면 `links`를 잃거나 남의 폴더를 차지하기 때문이다.

**다른 PC:** 서버가 이름이 바뀔 때 멤버들의 연결된 Agent에 `project.renamed`를 보낸다(사용자가 바꿔도, AI가 `set_project_info`로 바꿔도 같다). 꺼져 있던 PC는 연결할 때 받는 `project.names`와 세션·파일 탭 요청에 담긴 이름으로 따라온다. 이 PC에 폴더가 없는 프로젝트는 폴더를 만들지 않는다. 옛 Agent는 모르는 메시지를 로그만 남기고 넘어간다.

**믿는 이름과 믿지 않는 이름:** `project_dir(이름)`은 폴더를 찾기만 한다. 미리 띄우기(`state.json`)·대기 중인 케이스·세션 기록은 옛 이름을 들고 있어, 여기서 이름을 바꾸면 폴더가 되돌아간다.

**바꾸지 않는 것:** 직접 정한 작업 폴더(`links`), 스터디·케이스 폴더(번호로 찾는다), 사람이 탐색기에서 직접 지은 이름(프로젝트 이름이 다시 바뀌면 그때 따라간다), 사용자가 프로젝트 폴더를 다른 드라이브로 옮기고 이어 둔 링크(작업 공간 밖을 가리키는 접합. 대상이 없으면 빈 폴더를 만들지 않고 오류로 알린다).

**탐색기로 복사한 백업:** `P0012_이름 - 복사본`은 uid가 같아도 프로젝트 폴더로 쓰지 않는다. `index.json`이 가리키는 폴더가 진짜이고, 색인이 없으면 `project.json`의 `folder`가 자기 이름인 폴더가 진짜다(복사본은 원본의 이름을 들고 있다). 복사본의 이름도 바꾸지 않는다.

**특수한 이름:** 금지 문자·공백·`&%^!`·제어 문자는 `-`로 바꾼다. 끝의 점은 뺀다. `CON` 같은 예약어는 `P0012_CON`이라 문제없다. 쓸 글자가 없는 이름(빈 값, `...`)이면 폴더를 그대로 둔다. 24자까지 쓰고, 작업 공간 경로가 길면 8자까지 줄인다. 같은 번호·이름의 다른 프로젝트 폴더가 있으면(서버 DB를 다시 만든 경우) uid 앞 6자를 붙인다.

**번호만 있는 예전 폴더:**
- 그 폴더뿐이고 uid가 없거나 같으며 이름이 비어 있고 같은 서버의 것이면 그대로 받아 `P0012_<이름>`으로 바꾼다.
- 이름 있는 폴더가 옆에 있으면 안전할 때(그 폴더 안에 프로세스가 없을 때) 파일을 옮긴다. **덮어쓰지 않는다.** 내용이 같은 파일은 지우고, 이름이 같고 내용이 다른 파일은 번호 폴더에 남겨 파일 탭에 알린다. 다 옮기면 번호 폴더를 지우고 숨긴 접합을 남긴다.
- 지우는 것은 내용을 보고 DDS 것임이 확실한 파일뿐이다: 동기화 기록, 표시 구간 밖에 글이 없는 규칙 파일, DDS 스킬 폴더 안에서 배포본에 같은 이름이 있는 파일. 동기화 기록(숨김 목록)은 믿지 않는다. 그 뒤에 넣은 메모·`.claude/commands`·개인 스킬은 옮기거나 남긴다.
- 다른 uid·다른 서버의 폴더는 건드리지 않는다.
- 다른 `workspace_dir`에 있는 폴더(예: 개발 때 `~/DDS_Workspace`에 생긴 번호 폴더)는 Agent가 보지 않으므로 옮기지 않는다. 직접 정리한다.

번호 폴더가 생긴 원인은 상대 경로 `DDS_AGENT_CONFIG`였다. MCP의 cwd는 프로젝트 폴더라 설정을 못 찾고 기본값 `~/DDS_Workspace`에 만들었다. 이제 Agent가 설정·작업 공간·세션 폴더를 절대 경로로 넘긴다(`DDS_AGENT_CONFIG`·`DDS_WORKSPACE`·`DDS_PROJECT_DIR`·`DDS_PROJECT_UID`). 다른 프로젝트 번호를 받은 MCP는 서버에서 이름을 물어 폴더를 만든다.

**이름이 바뀐 뒤에도 그대로 되는 것:**
- 파일 탭·탐색기로 열기·뷰어: 사람에게 보이는 이름의 경로를 쓴다. 실제 이름이 다르면 파일 탭에 그 사실을 알린다.
- 케이스 폴더·다시 실행·Output 추가·학습 샘플: 서버의 절대 경로가 살아 있으면(옛 이름 접합) 실제 경로로 풀어 쓰고, 없으면 번호로 찾는다.
- 세션 불러오기(`session/load`): CLI마다 지난 대화를 찾는 법이 달라 따로 다룬다. 코드는 `main.py` `_load_cwds`, `session_history.py`. 2026-10-31 Windows 11에서 실제 프로그램·임시 설정 폴더로 확인했다(대화 턴은 돌리지 않았다).

| CLI | 찾는 법 | 실제 이름을 바꾼 뒤 | 확인 |
|---|---|---|---|
| Claude (claude-agent-acp 0.96) | `<설정>/projects/<실제 경로 인코딩>/<세션>.jsonl` 한 곳. 접합을 풀어 찾으므로 옛 이름을 넘겨도 못 찾는다 | 불러오기 직전에 기록(`<세션>.jsonl`·`<세션>\`)을 지금 경로의 폴더로 옮기고 지금 경로를 넘긴다 | 옮기기 전 `False`, 옮긴 뒤 `True`. 조작한 기록 파일로 시험 |
| Gemini (0.65) | 경로 문자열 그대로 | 시작한 문자열(`state.json` `session_cwd`)을 넘긴다. 이 버전 전에 만든 세션은 기억이 없어 지금 경로 → 옛 이름 접합 순서로 시도한다 | 지금 경로 `False`, 옛 이름 접합은 기록을 찾은 뒤 가짜 키에서 멈춤 |
| Codex (codex-acp) | 세션 id(rollout) | 지금 경로를 넘긴다 | 옛 이름·지금 경로 모두 `True`. 조작한 rollout으로 시험 |

옛 이름 접합으로 불러온 Gemini 세션은 cwd가 그 접합이라 실제 폴더를 다시 잠글 수 있다. 작업 공간이 git 저장소 안에 있으면 이 세션의 ripgrep 검색이 `exclude`의 접합 줄 때문에 결과를 못 찾을 수 있다(확인하지 못함).
- Claude 경로가 인코딩 뒤 200자를 넘으면 CLI가 이름에 해시를 붙여 맞힐 수 없다. 기록을 옮기지 않으므로 불러오기가 실패하고 지난 대화 요약으로 새 세션을 연다. 접합을 못 만드는 드라이브의 Gemini 세션도 옛 경로가 없어 같다.
- 규칙 파일의 스킬 목록: 프로젝트 폴더 기준 상대 경로라 낡지 않는다.
- `.git/info/exclude`: 옛 경로 구간을 지우고 새 경로 구간을 쓴다. git은 접합을 보통 폴더로 보아 같은 파일을 이름마다 새 파일로 잡으므로, 접합 이름(`visible`·`aliases`)을 프로젝트 번호별 구간에 적는다(끝에 `/` 없이).

**`project.json`의 기록:** `folder` 실제 이름 · `folder_for` 폴더 이름을 정할 때의 프로젝트 이름(없으면 한 번 맞춘다, 사람이 지은 이름을 알아보는 근거) · `visible` 접합으로 보여 주는 이름 · `aliases` 옛 이름 접합 · `pending` 실제 이름을 바꿀 차례를 기다림 · `want` 접합을 못 만들어 기다리는 이름 · `hid_real` 실제 폴더를 숨겨 둠 · `moving` 실제 이름을 바꾸는 중(끝나면 지운다) · `stray_wait` 번호 폴더가 아직 잠겨 있음 · `stray_names` 옛 이름 자리에 생긴 진짜 폴더 · `merged` 옮긴 파일 기록.

**알고 있는 부작용:** 접합 상태에서 폴더 아이콘에 화살표가 붙는다. "숨긴 항목 표시"를 켜면 같은 폴더가 여러 이름으로 보인다. 백업 프로그램은 접합을 건너뛸 수 있다. PowerShell 5.1의 `Remove-Item -Recurse`로 접합을 지우면 대상 폴더의 내용까지 지울 수 있으니 `cmd /c rmdir`을 쓴다.

**실제 프로그램으로 확인하지 못한 것:** 로그인한 CLI로 이름이 바뀐 폴더에서 대화 턴을 돌려 보지 않았다(불러오기까지만 위 표처럼 확인했고, 나머지는 가짜 CLI와 실제 cwd 잠금으로 시험). 지난 대화가 불러온 세션의 문맥에 실제로 들어가는지, Codex의 스킬 감시가 폴더를 잠그는지, Gemini MCP가 폴더를 잡는지, 숨긴 작업 폴더를 CLI의 검색 도구가 찾는지, 회사 보안 프로그램이 접합을 허용하는지, 탐색기가 접합을 어떻게 보여 주는지.

## 프로젝트마다 작업 폴더 직접 정하기
기본은 위처럼 `workspace_dir` 아래 `P0012_…` 폴더이지만, 사용자는 프로젝트마다 내 PC의 아무 폴더(예: `D:\Work\브래킷_개선`)를 작업 폴더로 정할 수 있다.

- 정하는 곳: 첫 화면 입력창의 **기본 폴더** 버튼(새 작업을 시작하기 전), 프로젝트의 **파일** 탭 "폴더 바꾸기", 프로젝트 메뉴 "작업 폴더 바꾸기".
  **찾아보기…**를 누르면 PC Agent가 내 PC에 Windows 폴더 선택 창을 띄운다. 경로를 붙여 넣어도 된다.
- 기록: 이 PC의 `index.json` → `"links": { "<프로젝트 uid>": "D:\\Work\\브래킷_개선" }`. 폴더는 **사람마다·PC마다** 다르다(서버에 저장하지 않음).
  멤버는 각자 자기 PC에서 정한다.
- 정한 폴더 안에도 위와 같은 구조(project.json·inputs·scripts·runs·studies·reports, 에이전트 규칙 파일)를 만든다.
  기존 파일은 옮기거나 지우지 않는다. 사용자의 CLAUDE.md·AGENTS.md·GEMINI.md에는 표시한 구간만 덧붙이고(아래 '규칙·스킬 파일 정리'), `project.json`이 이미 있으면 프로젝트 정보 항목을 더해 다시 쓴다.
  사용자 스킬 중 DDS 스킬과 이름이 같은 폴더에는 DDS 스킬 파일을 덮어쓴다.
- 쓸 수 없는 폴더: 드라이브 최상위(`C:\`), Windows·Program Files·ProgramData 아래, 다른 프로젝트가 쓰는 폴더(그 폴더의 project.json uid가 다름).
- 바꾸면 이미 만든 파일은 옮기지 않는다(이전 폴더에 남음). 숨긴 DDS 규칙·스킬과 사용자 규칙 파일의 DDS 구간도 그대로 남고, 지우는 기능은 없다. 그 폴더에서 CLI를 직접 쓰면 이 규칙을 계속 읽을 수 있다. 에이전트 CLI 세션은 시작 폴더가 고정이라, 내 대화는 다음 요청부터
  새 폴더에서 새 세션으로 이어 가고 지난 대화 요약을 함께 넘긴다. 에이전트가 작업 중이거나 이 PC에서 케이스를 실행 중이면 바꿀 수 없다.
- "기본 위치 사용"을 누르면 원래 `P0012_…` 폴더로 돌아간다.

## 규칙·스킬 파일 정리
사용자 폴더가 지저분해지지 않게 DDS가 만든 파일을 눈에 띄지 않게 둔다. 깔끔하게 하려는 것이지 **보호 수단이 아니다**(탐색기에서 "숨긴 항목"을 켜면 보인다). 코드는 `agent/dds_agent/context.py`.

- **숨기는 것(Windows Hidden 속성):** DDS만 만든 규칙 파일, 동기화 기록, `.claude`·`.gemini`·`.agents` 폴더. 동기화를 건너뛰는 때에도 맞춘다(파일 내용을 읽지 않고 이름·크기만 본다).
- **숨기지 않는 것:** 사용자 글이 들어 있는 규칙 파일, 다른 내용이 든 `.claude` 등의 폴더(그 안에서는 DDS 스킬 폴더만 숨긴다). 나중에 사용자가 그런 내용을 넣으면 DDS가 숨겼던 것을 다시 보이게 한다. 사용자가 직접 숨긴 것은 건드리지 않는다.
- **사용자 규칙 파일:** 표시한 구간(`DDS Conversa 규칙 시작`~`끝`)만 넣고 고친다. 구간 밖의 글은 바이트 그대로 남는다(인코딩·줄바꿈 포함). 기존 파일은 제자리에서 고쳐 권한(ACL)·하드 링크·이름의 대소문자도 그대로다. 구간을 지우면 다음 동기화 때 다시 들어간다.
  - 이 파일이 git에 올라가 있으면 **구간이 변경으로 보인다.** 팀이 같은 파일을 바꾸면 `git pull`이 멈춘다. 구간의 스킬 경로는 프로젝트 폴더 기준이라 이 PC의 경로는 들어가지 않는다.
- **지난 버전이 통째로 쓴 규칙 파일:** 처음 동기화할 때 옛 규칙과 스킬 목록을 빼고 구간 하나로 바꾼다. 제목 앞이나 스킬 목록 뒤에 덧붙인 글은 남기고, 그 글이 있으면 파일을 숨기지 않는다. 옛 규칙 본문 안을 직접 고친 내용은 사라진다(지난 버전도 업데이트 때마다 덮어썼다). 이미 덮어써진 사용자 파일은 되살리지 못한다.
- **웹 파일 탭:** 숨긴 항목을 목록에서 뺀다. 사용자 파일은 그대로 보인다.
- **git 저장소인 폴더(또는 그 안쪽 폴더):** 숨긴 항목을 `.git/info/exclude`에 프로젝트 경로별 구간으로 적어, 한 저장소의 프로젝트들이 서로의 항목을 지우지 않는다. `.gitignore`와 이미 추적 중인 파일은 건드리지 않으며, 저장소가 아니면 조용히 넘어가고 실패하면 다음 세션에 다시 시도한다. 저장소를 다시 만들었는지는 제외 목록과 `.geminiignore`의 크기로 알아챈다.
- **`.geminiignore`:** Gemini의 `read_file`이 exclude에 든 경로를 거부한다. 그래서 작업 폴더가 저장소 최상위이면 이 파일에 표시한 구간을 넣어 스킬 폴더를 다시 연다. DDS만 만들었으면 숨기고, 사용자 파일이면 보이게 둔다.
  - 이 파일이 git에 올라가 있거나 git이 실패해 올라갔는지 알 수 없으면 **고치지 않고 숨기지도 않는다.** 그때는 스킬 폴더를 exclude에 넣지 않아 **스킬 폴더가 git에 새 파일로 보인다.** `git add -A`로 올라갈 수 있지만, Gemini가 스킬을 못 읽는 쪽보다 낫다고 보았다.
- **Hidden 속성의 부작용:** PowerShell `Get-ChildItem`은 `-Force` 없이 이 항목을 보여 주지 않고, Node `fs.writeFileSync`·cmd `>`·`Out-File`은 숨긴 규칙 파일에 쓰지 못한다. 경로를 지정해 읽는 것은 된다. 규칙 파일의 스킬 목록 앞에 AI가 볼 안내를 적어 둔다.

CLI가 숨긴 파일을 찾는지 실제 프로그램으로 확인한 결과(2026-10-31, Windows 11).

| CLI | 규칙 파일 | 스킬 | 확인 방법 |
|---|---|---|---|
| Claude Code 2.1.316 | 읽음 | `alpha`·`beta` 모두 보임, Read·Glob 됨 | `claude -p` 2회 비교(보임 / 숨김+exclude). 표시 구간이 든 파일과 ACP가 쓰는 번들 2.1.310은 돌려 보지 않음 |
| Codex 0.165·0.166 | 읽음(기본 32KiB에서 잘려 PC Agent가 `project_doc_max_bytes`를 늘림) | 보임 | `codex debug prompt-input`을 저장소 안팎 6가지 배치에서 실행. codex-acp를 거쳐 설정이 전달되는지는 돌려 보지 않음 |
| Gemini CLI 0.65 | 읽음 | 보임(신뢰한 폴더만. 숨김과 무관) | `gemini skills list`와 파일 필터 `shouldIgnoreFile`을 같은 6가지 배치에서 실행. 대화 턴은 돌려 보지 않음 |

저장소 최상위에서는 Gemini의 `read_file` 필터가 `GEMINI.md`·`AGENTS.md`를 거부한다(exclude에 들어 있어서). 규칙 파일은 메모리로 읽으므로 스킬과 달리 다시 열지 않았다.

ripgrep은 Hidden 속성을 숨김으로 다뤄 `--hidden` 없이는 건너뛴다. Claude Code의 Grep은 `--hidden`을 쓰지만 exclude에 든 경로는 찾지 못하고, Read·Glob·스킬에는 영향이 없다.

## 원칙
- 원본(inputs)은 읽기 전용이다. 케이스는 원본을 복사해서 실행한다.
- 케이스 폴더는 지우지 않는다. 실패한 케이스도 `run.log`와 함께 남겨 원인을 추적한다.
- 프로젝트를 웹에서 삭제해도 로컬 폴더는 지우지 않는다. 정리는 사용자가 직접 한다.
- 경로 길이(260자) 때문에 폴더 이름은 짧게(최대 24자) 만든다. `workspace_dir`도 짧은 경로를 권장한다(예: `D:\DDS`).
