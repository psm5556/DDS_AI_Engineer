# 개발 인수인계 (집 PC → 사내)

작성: 2026-10-27. 집 PC(CAD/CAE 라이선스 없음)에서 개발했고, 이제 사내에서 사내 AI(Claude Code·Gemini CLI·Codex)와 함께 이어서 개발한다.
개발 규칙·디렉터리 지도·검증 명령은 [AGENTS.md](../AGENTS.md)에 있다. 이 문서는 **지금 상태와 다음에 할 일**을 다룬다.

## 2. 사내에서 먼저 할 일 (순서대로)
1. **서버 준비** — [onsite-ai-runbook.md](onsite-ai-runbook.md). 끝나면 관리 > Agent 배포 점검표가 모두 초록색.
2. **사용자 PC 1대 설치·연결** — 사이드바 아래에 그 PC 이름이 보이는지, CAD·CAE 툴 화면에 설치된 툴이 "바로 사용"으로 나오는지.
3. **데모로 전체 흐름 확인** — 첫 화면에서 AI를 "데모(시나리오)"로 고르고 "처음부터 끝까지" → 승인 → 허용 → 완료·보고서·Simulator.
   - 사내 AI는 `cd frontend; npm run smoke -- --demo`로 같은 확인을 할 수 있다.
4. **실제 AI CLI 연결** — Claude Code 등 사내에서 쓸 CLI로 짧은 요청을 한다. 예: "첨부한 파일 목록을 보여 줘"
5. **실제 툴 검증** — [onsite-validation.md](onsite-validation.md)의 툴별 요청을 대화창에 보낸다.
   - 실패하면 오류를 보고 스킬(`agent-context/skills/<툴>/`)을 고친다.
   - 고친 곳의 `TODO(사내검증)`을 지우고, 버전을 올려 배포한다.
   - 사내에서 실제로 쓰는 툴부터 한다.
6. **HPC** — 사내 스케줄러가 있으면 `onsite-validation.md` 4절대로 `[hpc]` 설정 후 케이스 1건.

## 3. 알려진 문제·확인 못 한 것
- **실제 CAD/CAE 연동 전부**: 스킬 스크립트·툴 API 호출은 공개 문서 기준으로 작성했다. 버전마다 API가 달라 첫 실행에서 고칠 곳이 나온다(`TODO(사내검증)` 약 560곳).
- **"찾아보기"(Windows 폴더 선택 창)**: 사용자 화면에 창이 떠서 자동 테스트를 못 했다. 안 되면 경로 붙여넣기로 쓸 수 있다.
  - 구현 위치: `agent/dds_agent/main.py`의 `_pick_folder`(tkinter).
- **개발 서버가 저절로 꺼진 일**: 집 PC에서 `dev_live.py`를 백그라운드로 돌릴 때 약 6분 만에 두 번 종료됐다(종료 코드 0, 로그에 오류 없음).
  - 같은 조건에서 25분간 재현되지 않았다. 이후 한 번 더 같은 일이 있었다(시작 약 6분 뒤).
  - 로그상 dev_live가 콘솔 Ctrl+C 신호를 받은 모양과 같다.
    - 대책으로 서버·Agent를 별도 프로세스 그룹으로 띄운다.
    - dev_live는 Ctrl+C를 3초 안에 두 번 받아야 끈다.
    - 꺼질 때는 이유를 `[dev_live]` 줄로 로그에 남긴다.
  - 운영 서버(uvicorn 서비스)는 dev_live를 쓰지 않는다. 그래도 같은 일이 있으면 시각과 로그를 남긴다.
- **모바일 화면**: 깨지지 않는 정도만 맞췄다(사용자 요청으로 데스크톱 우선).
- **번들 크기**: 프론트 JS가 약 5.7 MB(그래프 라이브러리 plotly). 사내망에서 첫 로딩이 느리면 그래프 화면을 지연 로딩으로 나눈다.
- **데모 프로젝트 이름 중복**: 데모를 여러 번 돌리면 같은 이름(브래킷 E2E 설계)이 쌓인다. 실제 AI는 요청 내용으로 이름을 붙인다.

## 4. 다음에 하면 좋은 것 (제안)
1. 실제 툴 검증 결과를 스킬에 반영하고 `TODO(사내검증)`을 줄인다(가장 중요).
2. 사내 표준 해석 템플릿(재료·하중·메쉬 규칙)을 스킬 `references/`에 넣어 에이전트가 사내 기준대로 모델링하게 한다.
3. 보고서 양식을 사내 양식(표지·목차·로고)으로 바꾼다(`server/app/report.py`).
4. 프로젝트·결과 검색(사이드바 검색은 이름만 찾는다).
5. 대형 결과(케이스 수백 개)에서 표·그래프 성능 점검.
6. 운영 DB를 SQLite에서 사내 DB로 옮길지 결정한다. `DDS_DB_URL`로 바꿀 수 있지만 검증은 SQLite만 했다.

## 5. 설계 결정 기록 (왜 이렇게 했나)
| 결정 | 이유 |
|---|---|
| 서버(웹·DB·학습)와 사용자 PC Agent(AI CLI·CAD/CAE 실행) 분리 | 라이선스·툴·무거운 결과는 각자 PC에 있고, 사내에서 쓸 수 있는 AI CLI도 각자 계정으로 PC에 인증돼 있다 |
| AI CLI는 ACP로 구동, 기능은 MCP 툴로 제공 | Claude·Gemini·Codex를 같은 방식으로 붙이고, 승인·권한 요청을 화면 카드로 받을 수 있다 |
| 실행 전 작업 흐름 제안 → 승인 | 프롬프트만 있는 도구는 사용자가 무슨 일이 일어나는지 몰라 쓰지 않는다. 흐름을 먼저 보여 주고 승인을 받는다 |
| 프로젝트 고유값(uid)으로 로컬 폴더 식별 | 서버 DB를 새로 만들어 번호가 겹쳐도 다른 프로젝트 폴더를 쓰지 않게 |
| 작업 폴더 직접 지정은 PC의 index.json에만 저장 | 경로는 그 PC에서만 의미가 있고, 멤버마다 다르다 |
| 설치 파일·런타임은 git에 넣지 않고 서버가 만든다 | 용량(약 250 MB)·라이선스·사내망. `prepare_onsite.py`가 서버의 Python·Node와 사내 미러로 만든다 |

| UI는 Claude·Codex 데스크톱 방식, 단계 최소 | 사용자 요구. 사이드바 1단계, 머리글에서 대화 전환, 오른쪽 패널 4탭, 중복 버튼 없음 |
| 화면 문구 한국어·쉬운 말 | 사용자가 AI 전문가가 아닌 CAE 엔지니어 |
