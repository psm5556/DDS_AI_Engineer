# 프로젝트 > 작업 최종 설계

표기는 **[확인]**(코드·패키지·실험·화면으로 본 것)과 **[판단]**(제 설계)입니다. 화면 문구는 모두 [판단]입니다.

- DECISIONS-work의 확정 사항은 다시 따지지 않았습니다.
- 문구 시험은 브라우저 안에서 문구만 바꿔 1440 폭에 들어가는지 잰 것이고, 서버 변경 요청은 0건입니다.
- 앞선 두 설계가 부딪친 곳은 이렇게 정했습니다.

| 부딪친 점 | 결정 | 이유 |
|---|---|---|
| 복사를 기본으로 켬 | **뺌.** 고르지 않으면 처음부터 | DECISIONS-work 확정 사항 |
| 폴더 이름 변경에 `지금 바꾸기` 버튼을 둠 | **뺌.** 접합으로 새 이름을 바로 보여 줌 | `folder-names` 구현이 이미 그렇게 함. "세션을 끝내지 않는다" 원칙과 맞음 |
| 번호만 있는 폴더(`W01`) 허용 | **안 만듦.** `W01_첫-작업`으로 시작 | 확정된 이름 규칙 |
| 세션을 작업 열 때 미리 불러옴 vs 타자 칠 때 | **타자 시작 때** | 구경만으로 세션이 살아나면 끝나지 않고 쌓임 |
| 모든 작업 보기·비교 화면 | **첫 범위에서 뺌** | 찾기는 검색으로, 비교는 요청으로 충족 |

---

## 1. 개념 다섯 줄

1. 프로젝트는 부품·제품 하나이고, 작업은 그 부품으로 하는 일 한 건입니다.
2. 작업 하나는 사람 한 명, PC 한 대, 폴더 하나, 기록 하나입니다. 결과도 모두 그 안에 있고 오른쪽 탭은 그 작업 것만 보여 줍니다.
3. 그냥 입력하면 아무것도 새로 생기지 않습니다. 새 모델로 보이면 앱이 묻고, 고르면 새 작업이 생기며 지난 것은 그대로 남습니다.
4. 남의 작업은 보기만 합니다. 이어서 하면 내 이름의 새 작업이 내 PC에 생깁니다.
5. 해석 중에도 입력창은 열려 있고, 작업 이름을 바꾸면 폴더 이름도 따라갑니다.

## 2. 용어 (3개)

| 말 | 뜻 |
|---|---|
| 프로젝트 | 부품·제품 하나 |
| 작업 | 그 부품으로 하는 일 한 건 |
| 폴더 | 내 PC에 작업마다 하나. 번호와 작업 이름으로 부름 |

- 화면에서 없애는 말: `대화`, `새 대화`, `세션`, `내 PC 작업 폴더`(프로젝트 폴더를 뜻하던 것).
- `프로젝트 폴더`는 프로젝트 메뉴에만, `DDS 저장 위치`는 설정과 트레이에만 나옵니다.
- `작업 흐름` 탭 이름은 "이 작업의 흐름"으로 읽히므로 그대로 둡니다.

**사용자가 외울 표**

| 하고 싶은 일 | 하는 법 | 새로 생기는 것 | 지난 것 |
|---|---|---|---|
| 하던 일 계속, 질문, 조건 바꿔 다시 | 그냥 입력 | 없음 | 그대로 |
| 같은 부품, 새 모델 | 파일을 놓으면 묻습니다. 또는 `새 작업` | 작업 + 폴더 | 그대로 |
| 다른 부품 | `새 프로젝트` | 프로젝트 + 첫 작업 + 폴더 | 그대로 |

## 3. 화면

### 3-1. 사이드바

```
Simulator
─────────
새 프로젝트
프로젝트 검색
[전체] [즐겨찾기] [보냄] [받음]
▾ 스파이더 경량화
    + 새 작업
    3차 M10 하중 변경     (진행 중)
    2차 M9 재검증 · 박프로
    2차 M9                (승인 대기)
    1차 경량화
    이전 작업 4개 더 보기
▸ 브래킷 3D Simulator     (실패)
▸ 허브 베어링 내구
```

| 항목 | 규칙 |
|---|---|
| 깊이 | 두 단계까지만 |
| 펼침 | 연 프로젝트는 항상 펼칩니다. 나머지는 화살표로 펼치고 접으며 상태를 기억합니다 |
| 프로젝트 줄 | 내 가장 최근 작업을 엽니다. 없으면 최근 작업, 작업이 없으면 새 작업 화면입니다 |
| 작업 순서 | 만든 순서, 최신이 위입니다. 활동 순이면 해석 중에 줄이 뛰어 잘못 누릅니다 |
| 긴 목록 | 5개까지 보이고 `이전 작업 N개 더 보기`로 펼칩니다. 지금 연 작업은 항상 보입니다 |
| 상태 | 작업 줄에 표시합니다. 프로젝트 줄은 접혔을 때만 가장 급한 것 하나를 보입니다 |
| 경고 집계 | 승인 대기·실패는 내 작업만 프로젝트 줄과 전체 아이콘에 올립니다. 남의 작업은 그 줄에 진행 중만 보입니다 |
| 남의 작업 | `2차 M9 재검증 · 박프로` |
| 검색 | 프로젝트 이름·설명, 작업 이름, 모델 파일 이름, 결과 제목을 찾습니다. 맞은 줄은 `1차 경량화 · 9월 12일 · spider_m7.prt`로 보입니다 |
| 접힌 레일 | 목록을 넣지 않습니다. 내 승인 대기·실패가 있으면 펼치기 버튼에 점을 찍습니다 |

마우스를 올리면 나오는 글:
- 새 프로젝트: `다른 부품이나 제품을 시작합니다. 폴더가 새로 생깁니다`
- 새 작업: `이 부품으로 새 일을 시작합니다. 폴더가 새로 생기고 다른 작업은 그대로입니다`

메뉴:
- 프로젝트: 지금 항목 그대로 (`폴더 바꾸기`는 여기 한 곳).
- 내 작업: `이름 바꾸기` · `폴더 열기` · `이 작업의 AI 끝내기` · `삭제`
- 남의 작업: 일반 멤버는 메뉴 없음. master·관리자는 `이름 바꾸기` · `삭제`

머리글 작업 이름의 ▾는 이 메뉴와 같습니다. 사이드바를 접어도 쓸 수 있어야 하기 때문입니다.

### 3-2. 첫 화면

```
[요청 입력창]
보내면 새 프로젝트와 첫 작업이 만들어집니다. 폴더는 내 PC의 DDS_Workspace 아래에 생깁니다.
이름 자동 · 기본 프로젝트 폴더

지난 작업처럼 시작 · 고르지 않으면 처음부터 합니다
  브래킷 경량화 › 2차 M9 · 나 · 6단계 · 질량 1.21 kg
  스파이더 경량화 › 1차 경량화 · 김엔지 · 8단계 · 질량 1.34 kg
  더 찾기

최근 작업 이어서 하기
  스파이더 경량화 · 2차 M9 · 승인 대기
```

지난 작업이 없으면 `지난 작업처럼 시작`은 보이지 않습니다. 목록은 내가 멤버인 프로젝트의 작업만 보여 줍니다.

### 3-3. 머리글과 주소

- 내 작업: `스파이더 경량화 ▾ / 2차 M9 ▾`
- 남의 작업: `스파이더 경량화 ▾ / 1차 경량화 · 김엔지 · 보기만 가능`
- 주소: `/projects/:pid/w/:wid`, `/projects/:pid/w/new`
- 옛 주소 `/c/:sid`는 그 작업으로, `/new`는 `/w/new`로 넘깁니다.

### 3-4. 새 작업 화면

`+ 새 작업`을 눌러도 아무것도 만들어지지 않고, 보낼 때 만들어집니다.

```
스파이더 경량화 / 새 작업

        이 부품으로 새 일을 시작합니다
보내면 작업과 폴더가 하나 생기고, 결과는 이 작업에만 모입니다. 다른 작업은 그대로입니다.

지난 작업처럼 시작 · 고르지 않으면 처음부터 합니다
  2차 M9 · 나 · 6단계 · 질량 1.21 kg
  2차 M9 재검증 · 박프로 · 6단계 · 질량 1.19 kg
  1차 경량화 · 나 · 8단계 · 질량 1.34 kg
[ 할 일을 적으세요. 모델 파일은 끌어 놓으면 됩니다        ↑ ]
```

고르면 목록 자리가 이 카드로 바뀝니다.

```
'2차 M9 재검증'처럼 시작합니다                    고르지 않기
가져오는 것: 작업 순서, 스크립트, 설계변수·범위, 목적·구속
가져오지 않는 것: 결과, 모델 파일 → 새 모델 파일을 끌어 놓으세요
```

해당할 때만 더하는 줄:
- 남이 만든 스크립트: `스크립트는 박프로님이 만들었습니다. 해석 전에 승인 카드에서 다시 확인합니다.`
- 다른 프로젝트에서 가져옴: `치수·경로·품번이 함께 옮겨질 수 있습니다. 문제 설정 카드에서 범위와 경로를 확인하세요.`
- 레시피 없음: `스크립트가 서버에 없어 작업 순서와 설정만 가져옵니다. AI가 스크립트를 새로 만듭니다.`

복사이며 연결이 아니므로 원본을 나중에 고쳐도 영향이 없습니다.

### 3-5. 오른쪽 탭

탭 다섯 개 모두 이 작업의 것만 보여 줍니다.

| 탭 | 빈 화면 또는 추가 문구 |
|---|---|
| 작업 흐름 | `아직 흐름이 없습니다. 해석을 돌릴 때 여기에 단계가 나타납니다` |
| 보고서 | `입력창에 "보고서 써 줘"라고 요청하세요` |
| 데이터 | `표를 붙여 넣거나 해석을 돌리면 여기에 쌓입니다`, 가져온 작업이면 맨 위에 `시작점: '1차 경량화'에서 가져옴 · 열기` |
| Simulator | 지금 문구 유지 |
| 파일 | 경로 첫 칸이 `P0012_스파이더-경량화 > W02_2차-M9 > …`. 남의 작업이면 `이 작업의 파일은 박프로님 PC에 있습니다. 서버에 있는 결과와 첨부는 내려받을 수 있습니다.` |

- 다른 작업의 소식은 탭을 빼앗지 않고 알림으로 띄웁니다: `'2차 M9' 해석이 끝났습니다 · 열기`
- 캔버스 버튼 안내: `결과 열기 — 작업 흐름·보고서·데이터 (Ctrl+J)`

### 3-6. 입력창

| 상태 | 안내 | 보내면 |
|---|---|---|
| 쉬는 중 | `이 작업에 요청하세요. 모델 파일은 끌어 놓으면 됩니다` | 바로 보냅니다 |
| AI가 답을 쓰는 중 | `보내면 이 단계가 끝난 뒤 답합니다` | 내 말풍선에 `대기 중 · 취소`. 대기는 1건이고 중지 버튼은 그대로 |
| 해석 중(AI는 쉼) | `해석은 계속됩니다. 질문해도 방해되지 않습니다` | 바로 답합니다 |
| AI 준비 중 | `AI 도구를 준비하는 중입니다. 회사 PC에서는 몇 분 걸릴 수 있습니다.` | 준비가 끝나면 답합니다 |
| 다시 잇는 중 | `이 작업을 이어 붙이는 중입니다.` | 끝나면 답합니다 |

## 4. 경로 규칙

### 4-1. 처리 순서

1. **표 붙여넣기**이면 표 질문으로 갑니다. AI를 거치지 않습니다.
2. **남의 작업**이면 카드 C를 보입니다.
3. **규칙 검사**(서버, AI 없음, 즉시)에 걸리면 카드 A·B·D를 보입니다. 요청은 아직 보내지 않습니다.
4. **걸리지 않으면 이 작업으로 보냅니다.**
5. **AI가 첫 단계에서 다시 봅니다.** 새 모델이나 다른 부품이 확실하면 아무것도 돌리지 않고 `suggest_route`를 부른 뒤 턴을 끝내고, 기록에 같은 카드가 나옵니다.
6. **안전망:** 놓쳐도 Flow 승인 전에는 돌지 않고, 새 스터디라 옛 결과는 다치지 않습니다.

**모르면 묻지 않고 "여기서 계속"입니다.** 세 갈래를 고르는 질문 창은 두지 않습니다.

### 4-2. 규칙 표

`결과 있음` = 이 작업에 스터디나 승인된 흐름이 1개 이상.

| 입력 | 조건 | 결과 |
|---|---|---|
| 모델 파일 놓음(`.prt .sldprt .catpart .stp .step .igs .iges .x_t .x_b .cae .inp .k .key .bdf .fem .sim`) | 결과 없음 | 카드 없음 |
| 위와 같음 | 결과 있음, 이 작업 첨부와 sha256이 같음 | 카드 없음 |
| 위와 같음 | 결과 있음, 내용이 다름(이름이 같아도) | **놓는 즉시 카드 A** |
| 모델 아닌 파일 | — | 카드 없음 |
| 글: `새 모델` `신규 모델` `새 버전` `개정` `다음 모델` | 결과 있음, 같은 문장에 `학습` `예측` `Simulator` `배포`가 없음 | 보낼 때 카드 A |
| 글: `다른 부품` `다른 제품` `완전히 다른` `새 프로젝트` | — | 보낼 때 카드 B |
| 첫 화면 글에 기존 프로젝트 이름 전체가 있음 | 내가 멤버 | 카드 D |
| 그 외(`다시`, `새로`, 하중 변경, 질문) | — | **카드 없음** |

- `Attachment`에 이미 `sha256`이 있습니다 [확인]. 개정판을 같은 파일 이름으로 올려도 잡을 수 있습니다.
- `학습` 등을 뺀 이유는 "새 모델 학습해 줘"가 예측 모델 이야기이기 때문입니다 [판단]. 앞선 설계에 없던 오탐입니다.
- `.dat`은 표일 수 있어 뺐습니다. 부품 이름만으로 다른 부품인지는 5번 AI가 잡습니다.

### 4-3. 카드: 한 문장, 주 버튼 하나

| 카드 | 문장 | 주 버튼 | 글자 링크 |
|---|---|---|---|
| A 새 모델 | `새 모델 spider_m9.prt로 보입니다. 새 작업은 '1차 경량화'의 작업 순서·스크립트·설정을 가져와 시작하고, 지금 작업은 그대로입니다.` | `새 작업으로 시작` | `여기서 계속` |
| A 파일 없음 | `새 모델 이야기로 보입니다. 새 작업은 '1차 경량화'의 작업 순서·스크립트·설정을 가져와 시작하고, 지금 작업은 그대로입니다.` | `새 작업으로 시작` | `여기서 계속` |
| B 다른 부품 | `다른 부품으로 보입니다. 새 프로젝트로 폴더와 결과를 따로 시작하고, 지금 프로젝트는 그대로입니다.` | `새 프로젝트로 시작` | `여기서 계속` |
| C 남의 작업 | `박프로님의 작업이라 보기만 할 수 있습니다. 이 요청은 내 이름의 새 작업으로 내 PC에서 이어서 하고, 원래 작업은 그대로입니다.` | `이 작업을 내 PC에서 이어서 하기` | `취소` |
| D 첫 화면 | `'스파이더 경량화' 프로젝트가 이미 있습니다. 그 안에 새 작업으로 시작하면 지난 스크립트·설정을 이어 씁니다.` | `그 프로젝트에 새 작업` | `새 프로젝트로 계속` |

## 8. 폴더

```
P0012_스파이더\
  project.json
  (숨김) CLAUDE.md AGENTS.md GEMINI.md .claude .gemini .agents      ← 스킬 1벌
  inputs scripts runs studies live reports                          ← 기존 프로젝트에만
  W01_1차경량화\                                                    ← AI의 cwd
    work.json
    (숨김) AGENTS.md GEMINI.md .gemini\settings.json .dds-work-stamp
    inputs scripts runs studies live reports
```

- **만드는 때:** AI 시작이나 케이스 실행 때만입니다. 조회로는 절대 만들지 않습니다.
- **찾는 순서:** `W{seq:02d}_*` → `work.json` uid 확인. 번호가 같고 uid가 다르면 uid 앞 6자를 붙입니다.
- **첫 이름:** `+ 새 작업`이면 요청문 앞부분이나 모델 파일 이름, 새 프로젝트면 `첫 작업`입니다.
- **다른 PC의 내 작업:** 폴더가 없으면 새로 만들고 서버의 스크립트와 첨부를 받습니다. 세션은 요약으로 잇습니다 [판단].
- **직접 고른 프로젝트 폴더:** 프로젝트 폴더 이름은 그대로, 작업 폴더만 규칙을 따릅니다. 원본은 cwd의 한 단계 위라서 규칙에 "원본은 `../`에 있을 수 있다. 읽기만 한다"를 넣습니다.
- **경로 길이:** 기본 위치에서 `fields\`까지 150자, 파일 이름 109자 남음 [계산]. `_fit` 여유를 프로젝트 139, 작업 110으로 나눕니다.
- **이름 변경:** `sync_name`을 "부모 폴더 + 앞머리 + 기록 파일" 인자로 일반화합니다. 순서는 작업 → 프로젝트 → 작업 접합 재생성입니다. 부모 이름을 바꾸면 안쪽 접합이 끊어지기 때문입니다 [확인: 실험].

### 규칙·스킬: 468개 대신 4개

스킬 33개, 156개 파일 × 3벌 = 468개, 약 5.4 MB [확인].

| CLI | 규칙 | 스킬 | 프로젝트 폴더 읽기 |
|---|---|---|---|
| Claude | 부모의 `CLAUDE.md` | 부모 `.claude/skills` 자동 | `additionalDirectories` |
| Codex | 작업 폴더 `AGENTS.md` | `additionalDirectories`의 `.agents/skills` + 규칙 파일 목록 | 같음 |
| Gemini | 작업 폴더 `GEMINI.md` | 규칙 파일의 `../.gemini/skills/…` | `.gemini/settings.json` `context.includeDirectories` |

- 패키지를 읽어 확인했고 실행은 안 했습니다. 이번에 다시 본 것: claude-agent-acp와 codex-acp에 `additionalDirectories`, claude-agent-acp에 `session/close`, Gemini 번들에 `GEMINI_CLI_TRUSTED_FOLDERS_PATH`와 `includeDirectories`.

- `CLAUDE.md`를 작업 폴더에 두지 않습니다. 두면 Claude가 규칙을 두 번 읽습니다.
- `_skill_index`는 `../` 상대 경로로 바꿉니다.
- git 제외는 프로젝트 구간에 `W*/AGENTS.md` 같은 패턴만 더합니다.
- Gemini 신뢰는 DDS 전용 목록(`~/.dds-agent/`)을 `GEMINI_CLI_TRUSTED_FOLDERS_PATH`로 넘깁니다 [판단]. 사용자의 전역 파일은 고치지 않고 신뢰 검사 전체를 끄지도 않습니다.
- 알고 맡기는 위험: `additionalDirectories`는 형제 작업 폴더에도 쓰기를 허용합니다. 옛 결과 보호는 규칙("다른 작업 폴더는 읽기만")에 맡깁니다 [판단].
- 실패 때 대안: 관문 G1~G6을 통과하지 못한 CLI에만 작업 폴더에 스킬을 복사합니다(작업마다 156개).

## 10. 이전

시작할 때 `ensure_columns` 뒤에 `migrate_works`가 돕니다. 여러 번 돌아도 결과가 같습니다.

1. 처음 한 번 DB를 백업합니다.
2. 자료가 있고 작업이 없는 프로젝트마다 `seq=0, legacy=True, name="이전 기록"`을 만듭니다.
3. 주인은 가장 최근 대화의 사용자, 대화가 없으면 프로젝트 주인입니다.
4. `legacy_users`는 대화·케이스 실행·모델 생성·첨부 기록이 있는 멤버입니다.
5. 표의 `work_id IS NULL` 행을 채웁니다. 첨부는 보내기 전 임시 행이 끼지 않게 첫 이전 때만 채웁니다.

| 질문 | 답 |
|---|---|
| 대화가 여럿이면 | 시간순 한 기록. 경계 줄: `이전 기록 · 박프로 · 9월 12일` |
| 결과를 대화별로 나누나 | 안 나눕니다. 도구 메시지 190개 중 `flow_id`·`study_id`가 있는 것은 30개뿐입니다 [확인: 데모 DB] |
| 입력창이 보내는 곳 | 그 기록 안 내 최근 대화. AI가 그대로 이어집니다 |
| 옛 폴더 | 옮기거나 이름을 바꾸지 않습니다. 새 작업부터 그 안에 `W01_…`이 생깁니다 |
| 살아 있는 AI | 그대로. cwd가 같습니다 |
| 파일 탭 | 프로젝트 폴더를 보이되 `work.json`이 있는 `W*`는 뺍니다 |
| 첫 안내 | 한 번만: `대화가 작업으로 바뀌었습니다. 지금까지의 기록은 '이전 기록' 작업에 모았습니다. 새 일은 '+ 새 작업'으로 시작하세요.` |
| 되돌리기 | 옛 서버는 새 열을 무시합니다. 그때 생긴 행은 다음 시작 때 채웁니다 |

- 실제 CLI 세 개로 작업 폴더 구조를 돌리지 않았습니다. 2단계 관문이 이를 잽니다.
