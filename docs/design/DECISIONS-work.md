# 프로젝트와 작업 구조: 사용자 결정 (2026-10-31)

사용자 원문: "작업마다 폴더 하나로 진행해주세요. 그러면 사이드바도 프로젝트 아래 작업이 하이라키 구조로 붙어야 하는거 아닌가요?"
앞선 원문: "새모델을 할때는 작업폴더가 새로 만들어지는건지? 새대화일때는 어떻게 되는건지? 너무 어렵습니다."

확정:
- 화면의 단위는 프로젝트 > 작업 두 단계. "대화"는 화면 개념에서 없애고 작업 안에 포함. "새 대화" 버튼 없앰.
- 작업마다 폴더 하나: P0012_스파이더\W01_1차경량화\ 아래에 inputs, scripts, studies, reports 등. 작업의 대화·흐름·결과·Simulator·보고서가 그 작업에 묶인다.
- 사이드바는 프로젝트 아래 작업이 붙는 계층 구조. (AGENTS.md와 Sidebar 주석의 "사이드바는 한 단계만" 원칙을 이 결정으로 바꾼다.)
- 새 모델로 같은 일: 새 작업 + 새 폴더, 지난 스크립트·설정을 복사해 시작, 옛 폴더와 결과는 그대로. 다른 부품: 새 프로젝트 + 새 폴더. 하던 일: 아무것도 안 생김.
- 이름 규칙: 폴더 W01_<작업이름>, 작업 이름을 바꾸면 폴더 이름도 따라간다(프로젝트 폴더와 같은 규칙).

사이드바 초안(제 판단):
- 열린 프로젝트는 항상 펼침, 나머지는 화살표로 펼침·접기, 펼친 상태 기억.
- 프로젝트 줄을 누르면 가장 최근 작업이 열림. 작업 줄을 누르면 그 작업이 열림. 작업 줄에 상태 표시(진행 중·승인 대기·실패).
- 필터 아이콘 4개와 프로젝트 검색은 프로젝트 기준을 유지하되, 검색은 작업 이름도 찾아 해당 프로젝트를 펼친다.
- 깊이는 두 단계까지만.

사용자 확정 (2026-10-31): "사람별로 새 작업 만드는 방식으로 진행해주세요. 공유받은 것은 보기만 가능한거죠?" → 이어받기는 사람별 새 작업으로 확정. 남의 작업은 보기만: 대화·흐름·결과·보고서 열람, 파일·결과 내려받기, Simulator 사용(예측)은 가능. 재학습, 배포, 해석 실행·중지, Output 추가, 보고서 다시 쓰기, 이름 변경, 삭제는 작업 주인만. 지금 코드는 멤버가 남의 스터디를 재학습·배포할 수 있으므로 서버 API에서 막는다(화면만 숨기지 않는다). 프로젝트 관리자(master)는 작업 이름 변경·삭제 가능, 실행은 불가. 관리자 계정(관리부서)도 남의 작업 실행은 불가. Simulator 공유 링크로 받은 사람은 예측만. 프로젝트 안에서 멤버는 자기 작업을 언제든 새로 만들 수 있다.
공유 받은 사용자 (사용자 질문 2026-10-31: "혼자 작업에는 지금 구조 좋습니다. 공유후에 다른 공유받은 사용자가 공유받은 사용자의 PC에서 이 프로젝트를 수행할때는 어떻게 되는건가요?"). 위 확정 내용을 따른다:
- 웹의 프로젝트·작업 구조는 모두에게 같다. 폴더는 PC마다 따로 있고 번호와 이름이 같다. 내 PC에 없는 작업 폴더는 그 사람이 그 작업을 이어받을 때만 생긴다.
- 작업 하나는 한 사람이 한 PC에서 진행한다(AI 세션이 그 PC에 있으므로). 남의 작업은 결과·대화를 볼 수 있고, 입력창에 쓰면 "이 작업을 내 PC에서 이어서 하기" 한 문장·한 버튼. 누르면 같은 프로젝트에 내 이름의 새 작업이 생기고 내 PC에 그 폴더가 만들어지며, 서버의 스크립트·설정(레시피)과 첨부 입력 모델을 내려받고 지난 대화 요약을 AI에게 넘긴다. 원래 작업은 그대로 남는다.
- 사이드바 작업 줄에 다른 사람의 작업이면 이름을 표시(예: 2차 M9 · 박프로). 필요한 툴이 내 PC에 없으면 시작 전에 알린다.
- 올라가지 않은 원본(odb 등)은 받을 수 없다는 점을 이어받기 전에 알린다. 남이 만든 스크립트 실행은 승인 카드에 누가 만들었는지 표시.

새 작업·새 프로젝트 시작 (사용자 2026-10-31: "새 작업을 만들때는 기존작업의 흐름을 가져올지 물어보면 어떨까요? 그냥은 사용자가 다른 작업의 흐름을 가져올 수 있는지 모를것같습니다. 새 프로젝트를 만들때도 필요하지 않을까요?") 반영:
- 새 작업: 입력창 바로 위에 "지난 작업처럼 시작" 목록을 보여 준다(같은 프로젝트의 작업, 최근순, 만든 사람·흐름 단계 수·결과 한 줄). 고르지 않고 바로 입력하면 처음부터. 창을 따로 띄워 막지 않는다. 지난 작업이 없으면 아예 보이지 않는다.
- 새 프로젝트: 첫 화면 입력창 아래 같은 형태. 내가 볼 수 있는 프로젝트의 작업에서 고른다(최근 몇 개 + 검색). 첫 사용자는 지난 작업이 없으므로 보이지 않는다.
- 고르면 카드에 가져오는 것을 그대로 적는다: 작업 순서, 스크립트, 설계변수·범위, 목적·구속. 가져오지 않는 것: 결과, 모델 파일(새 파일을 넣어 달라고 안내). 스크립트는 내 PC로 내려받고 해석 전에 승인 카드(남이 만든 스크립트면 이름 표시). 값은 문제 설정 카드에 미리 채워 고칠 수 있게 한다.
- 복사이며 연결이 아니다. 원본 작업을 나중에 고쳐도 내 작업은 그대로. 어느 작업에서 가져왔는지 기록해 표시.
- 다른 프로젝트에서 가져오기는 내가 멤버인 프로젝트만. 기밀 값(치수·경로·품번)이 함께 옮겨질 수 있으므로 설계변수 범위와 경로를 확인하게 한다. 내 PC에 스크립트가 없어도 서버 레시피로 가능, 레시피가 없으면 흐름 단계와 설정만 가져오고 안내.

2. 해석이 끝나면 승인된 흐름 안에서만 서버가 AI를 깨워 다음 단계를 잇는다. 해석 중 입력창을 연다.

상황 지도(research/situ-final.md, 장치 M1~M8, 13단계 순서) 결정 (사용자 2026-10-31: "복사로 해주세요. 떠난사람은 일단 나중에 정할께요."):
- 버튼 문구는 `내 PC로 복사해서 하기`. "이어서"를 쓰지 않는다. 말 사전: AI 계속하기 / 남은 해석 돌리기 / 내 PC로 복사해서 하기 / AI 멈춤 / 해석 중지.
- 떠난 사람의 작업(주인 넘기기, 14일 기록 정리)은 보류. 구현하지 않고 사용자에게 다시 묻는다.
- 승인 뒤 자동 범위(결정 1) 사용자 확정: "무조건 끝까지 갑니다. 단 중간에 사용자가 프롬프트로 계획변경이나 요청ㄹ하면 빠꿔주면 됩니다." → 승인 뒤에는 묻고 멈추지 않는다. situ-final.md의 "멈추고 묻기"(실패, 정확도 낮음, 범위 초과, 1시간 재확인, CR-02 카드)를 이 결정으로 뒤집는다. 세부(제 판단, 사용자에게 알림):
  - 실패가 있으면 AI가 스스로 고치고 다시 돌려 진행. 성공한 데이터로 끝까지 가고 결과에 실패 수를 사실로 표시. 환경 원인(라이선스 등)으로 큐를 잠깐 멈춰 낭비를 줄이되 사람을 기다리지 않고 AI를 깨워 재시도. 물리적으로 계속할 수 없을 때만 상태 "멈춤"과 이유.
  - 정확도 낮음이어도 끝까지, 결과와 보고서에 사실 표시.
  - 승인 뒤 PC가 꺼져 있으면 연결되는 대로 자동 시작(1시간 재확인 없음).
  - 공유 중인 Simulator가 더 나빠지는 경우: 흐름은 멈추지 않고 새 버전을 만들어 두되, 공유 링크 값은 바꾸지 않고 주인이 고를 수 있게 표시(남의 판단 자료가 말없이 바뀌는 것을 막음).
  - 사용자가 중간에 프롬프트로 계획 변경·요청을 하면 AI가 받아 계획을 바꾼다. 사람의 마지막 지시가 우선. 돌던 해석을 끝낼지는 요청에 따른다.
  - 승인 전 관문(승인 카드, 문제 설정 카드)은 그대로. 처음 승인 범위를 넘어 AI가 해석을 크게 늘리는 경우는 상태 줄과 결과에 표시.

설계에 반영: 세션 작업 폴더(cwd)는 작업 폴더. 기존 프로젝트 이전(기존 대화·흐름·스터디를 작업 하나로 묶거나 대화별로 나누는 규칙, 옛 폴더는 건드리지 않고 그대로 두고 새 작업부터 적용할지), 멤버 이어받기, 레시피, 파일 탭 범위, 표로 만든 Simulator가 어느 작업에 들어가는지, 긴 해석 중 다른 일 하기.
