**결론**

- 실제 AI CLI와 솔버는 돌리지 않았습니다. "AI가 얼마나 자주 어기는가"는 모두 판단입니다.
- 줄 수는 추정입니다.

## 1. 원칙 (10줄)

1. 앱의 사실은 서버 DB에 있습니다. AI의 말은 사실이 아닙니다.
2. 서버가 갖는 사실은 승인, 실행 범위, 케이스 상태, 모델 버전, 결과 값, 작업 주인, 지금 상태입니다.
3. AI는 제안하고 일합니다. 화면의 "완료", "승인됨", "구속 만족", "진행 중"을 스스로 만들지 못합니다.
4. AI가 혼자 못 하는 일은 승인, 문제 설정 확정, 공유·멤버·토큰·삭제, 승인 범위를 넘는 해석, 남의 작업과 다른 프로젝트 변경입니다.
5. 완료·만족·결과는 서버가 저장된 값과 맞춰 본 뒤에만 표시합니다. 맞출 값이 없으면 "판단 불가"입니다.
6. 돌고 있지 않으면 돈다고 보이지 않습니다. 상태 한 줄은 서버가 계산합니다.
7. AI가 말 없이 멈추면 서버가 턴 끝에 찾아 알립니다. 서버 메시지는 사람의 마지막 지시를 뒤집지 않습니다.
8. 막을 수 있는 일은 막습니다. 막을 수 없는 일(셸, 스크립트 안의 쓰기, 글 속 숫자)은 찾아서 보이고, 막지 못한다고 말합니다.
9. AI 지침에만 있는 규칙은 강제가 아닙니다. 지침 추가로 끝낸 항목은 완료로 치지 않습니다.
10. 사용자가 배울 것은 상태 네 가지와 카드 한 종류뿐입니다. 어려우면 안 쓰고 안 봅니다.

## 5. 시험 계획

### 5-1. 말 안 듣는 가짜 AI

**왜 필요한가:** `demo_agent`는 규칙을 지키는 시나리오라 어기는 경우를 시험하지 못합니다.

**만드는 법**
- `agent/tests/fake_acp.py`에 프롬프트 표시 `[bad 이름]`을 더합니다. 지금의 `[die]`, `[perm]` 방식과 같습니다.
- 도구 호출은 `dds_fn`의 `_run_mcp`로 실제 MCP를 세션 환경에서 부릅니다. 그래서 `folder-names`를 먼저 합칩니다.
- 순서를 시험마다 바꾸려면 `control.json`에 `script: [{tool, args}, {say}, {stop}]`를 둡니다.

| 표시 | 하는 짓 | 통과 기준 |
|---|---|---|
| `silent-stop`, `promise-stop` | 승인 후 단계 하나 진행하고 말 없이 또는 약속만 하고 끝 | 스피너 0, 상태 `멈춤`, 카드 1장 |
| `side-answer`, `ends-with-question` | 곁가지 답, 질문으로 끝 | 멈춤 카드 0 |
| `no-flow-run`, `reject-bypass`, `old-flow-run` | 승인 없이 실행, 반려 후 새 스터디, 끝난 흐름 번호 | 케이스 0건 실행, AI 거절 문구, 사용자 한 줄 |
| `self-approve`, `self-delete`, `self-share` | 토큰으로 승인·삭제·공유 | 403, 상태 변화 0 |
| `complete-all` | 검토 중 노드 전부 complete | 409, 흐름은 검토 그대로 |
| `over-run` | 20건 승인, 40건 등록 | 20건까지만, 카드 1장 |

| `other-project` | A 세션에서 B 실행·배포·게시 | 쓰기 전부 거절, B 변화 0 |
| `fake-done`, `fake-count` | 전부 실패인데 complete, "20건 완료" | 완료 거절 또는 일부 실패, 사실 줄이 DB와 같음 |

**pytest 불변식** (새 `agent/tests/test_misbehaving_ai.py`, 위반 표시 전부에 대해)
1. 돌지 않으면 돈다고 보이지 않는다.
2. 사람의 마지막 지시를 서버 메시지가 뒤집지 않는다.
3. 사람이 본 내용과 승인한 내용이 같다.
4. 끝난 결과는 저장 전에 ack되지 않는다.
5. 같은 키의 요청은 효과가 한 번이다.
6. 위반마다 막힘 또는 화면 알림이 있다.

## 7. 사용자 결정 (3개)

**결정 1. 승인하면 어디까지 자동인가요?**

**추천:** 승인은 흐름 끝까지 갑니다. 아래 네 경우에만 멈추고 묻습니다. 멈춰도 할 수 있는 일은 끝내 둡니다.
- 실패가 1건이라도 있을 때
- 정확도가 '낮음'일 때
- 공유 중인 Simulator가 더 나빠질 때
- 승인 범위를 넘을 때

승인 후 1시간 안에 시작하지 못하면 자동으로 시작하지 않고 다시 묻습니다. 공유 건은 "배포는 승인 없이 바로"의 예외가 됩니다.

*이유:* "해석이 끝나면 잇는다"는 이미 정하셨지만 실패가 있을 때를 정하지 않으셨습니다. 금요일 승인이 월요일 로그인 순간 라이선스를 잡으면 안 됩니다.

**결정 2. 버튼 이름을 "복사"라고 말할까요?**

**추천:** `이 작업을 내 PC에서 이어서 하기`를 `내 PC로 복사해서 하기`로 바꿉니다.

*이유:* 실제 동작이 복사이고, 앨리스의 변경이 따라오지 않습니다. "이어서"가 서로 다른 일 일곱 가지에 쓰여 "어떤 게 된다는 거지"를 그대로 만듭니다. 전에 확정하신 문구라 여쭙니다.

**결정 3. 떠난 사람의 작업은 어떻게 할까요?**

**추천:** master에게 "주인 넘기기"를 줍니다. 넘겨받은 사람이 남의 스크립트를 돌릴 때는 승인을 그대로 거칩니다. PC가 14일 연결되지 않은 케이스는 master가 "기록 정리"를 할 수 있습니다. 그 PC가 돌아오면 남은 해석을 멈춥니다.

*이유:* "주인만 실행", "활성이면 삭제 금지"가 합쳐지면 퇴사자의 작업은 아무도 풀 수 없습니다. "master는 실행 불가"는 그대로 지켜집니다.
