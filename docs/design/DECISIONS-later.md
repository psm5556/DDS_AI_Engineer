# 사용자 결정 (2026-10-31)

사용자 원문: "A와 C는 적용해야 겠네요." (그 직전에 "일단 이부분은 적용하지 마세요"라고 했다가 바꿈. 최신 말이 우선)

- A 적용: 프로젝트 작업 폴더의 규칙 파일·스킬 폴더를 숨김 처리. 보안이 아니라 정리 목적.
- C 적용: 핵심 로직은 서버에서 실행. 코드가 PC로 가지 않게 한다. 비파라미터 형상부터. PC의 툴에서 돌아야 하는 것은 제외.
- B(스킬을 서버에서 필요할 때만 전달): 적용 안 함. 말이 있을 때만.
- D(난독화): 안 함.

사용자 질문: "사용자들이 작업한 것을 서버에서 회사의 자산으로 스킬화나 툴화를 해서 우리 프로젝트가 점잠 완성형이 되게 할수도 있나요?"
→ 가능하다고 답하고 설계부터 한다. 구현 여부는 설계 뒤.

사용자 답 (2026-10-31): HTTPS는 추후 고려. 서버 사양은 향후 사내에서 확인. 자산화의 회사 정책은 "문제 없습니다"(소유·공유 범위 문제없음으로 이해, 정리 담당은 관리부서로 가정). 덱 서버 업로드: 사용자 "서버에 올리면 안되는 덱은 없습니다." → 항상 허용. 프로젝트별 금지 설정(geometry_upload)은 만들지 않는다. 첫 업로드 때 대화 안내와 삭제 버튼은 유지.

용어: 아하 모먼트 = 진짜 사람이 할 수 없는 것 / 킬러 기능 = 웹앱의 주요 기능.
