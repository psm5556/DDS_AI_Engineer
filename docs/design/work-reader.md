# 프로젝트 > 작업 설계 비판 검토

**결론 [판단]:** 구조는 이해됩니다. 다만 구현 전에 설계를 고쳐야 할 곳이 7개 있습니다.

- 파일을 놓고 글을 쓴 뒤 Enter를 누르면 조용히 옛 작업에 섞입니다.
- 같은 작업에서 다시 돌리면 지난 결과 카드를 덮어씁니다.
- 시나리오 7의 요청 자체가 새 작업 카드를 띄웁니다.
- 검증되지 않은 접합이 예외가 아니라 모든 새 프로젝트의 기본 경로입니다.
- 어느 스터디를 복사하는지, 폴더를 바꾸면 무슨 일이 생기는지가 설계에 없습니다.
- 이어받기에서 3D 필드가 빠집니다.

**확인한 범위**
- 표기는 **[확인]**(코드·실험)과 **[판단]**입니다.
- 코드는 작업 트리, `origin/main`, `folder-names`(`dds_fn`)를 읽었습니다.
- 화면은 저장된 이미지 5장만 봤고, 앱은 새로 띄우지 않았습니다.
- 실험은 임시 폴더의 접합 하나뿐이고, 저장소와 서버는 건드리지 않았습니다.
- DECISIONS의 확정 사항은 다시 따지지 않았습니다.

## 2. 문제와 고칠 내용

### 구현 전에 설계를 고칠 것

**P1. 파일을 놓고 글을 쓴 뒤 Enter를 누르면 옛 작업에 섞입니다. [판단: 설계 해석]**
- 카드 A는 파일을 놓는 순간 뜨는데, 설계는 "Enter를 한 번 더 누르면 글자 링크"라고 합니다.
- 놓기, 쓰기, Enter가 가장 흔한 순서이고, 이때 첫 Enter가 `여기서 계속`이 됩니다.
- `여기서 계속`을 고른 파일은 다시 묻지 않고 AI에도 알리므로 4-1의 5번 안전망도 꺼집니다.
- 카드 D에서는 Enter가 `새 프로젝트로 계속`이 되어 폴더가 생깁니다. "실수로 폴더가 생기지 않게"와 반대입니다.
- **고침:**
  - 카드가 떠 있으면 Enter와 보내기 버튼은 아무것도 보내지 않고 글을 그대로 둡니다.
  - 카드 아래에 `위에서 먼저 골라 주세요`를 표시합니다.
  - 카드 버튼은 Tab으로 갈 수 있게 합니다.
  - `smoke.mjs`에 "놓기→입력→Enter 후 전송 0건"을 넣습니다.

**P2. "지난 결과는 그대로 남습니다"가 같은 작업 안에서는 거짓입니다. [확인: `service.py` `publish_artifact`]**
- 지금은 `project_id+title`로 찾아 내용을 덮어쓰고 `flow_id`도 새 흐름으로 옮깁니다.
- 설계대로 `work_id+title`로 바꾸면 다른 작업은 지켜지지만, 시나리오 4의 재실행은 같은 제목의 옛 카드를 덮어씁니다.
- **고침:**
  - 찾는 키를 `work_id + flow_id + title`로 합니다. 흐름이 없으면 `work_id + title`입니다.
  - `art.flow_id = flow_id or art.flow_id` 줄을 없앱니다.
  - `test_works_api.py`에 "같은 작업, 흐름 2개, 같은 제목이면 행 2개"를 더합니다.

**P3. 글 규칙이 설계의 시나리오를 스스로 막습니다. [확인: 4-2 규칙으로 대입]**
- 결과가 있는 작업에서 아래 문장은 모두 카드 A가 뜹니다.
  - `새 모델과 옛 모델 비교해 줘` (시나리오 7은 "새 작업은 생기지 않습니다")
  - `지난달 새 모델 결과 어디 있어?`
  - `새 버전 보고서 써 줘`
  - `개정 규격대로 허용 응력 바꿔 줘`
- **고침:**
  - `개정`, `새 버전`, `다음 모델`을 규칙에서 빼고 AI 판단(`suggest_route`)으로 넘깁니다.
  - 남는 규칙은 `(새|신규) 모델(로|으로|을 돌려|이 나왔)`뿐입니다.
  - 같은 문장의 제외어에 `비교 결과 어디 찾아 보여 보고서 ?`를 더합니다.
  - 위 네 문장을 `test_route_check.py`의 오탐 항목에 넣습니다.

**P4. 어느 스터디를 가져오는지 정해져 있지 않습니다. [확인: 설계에 규칙 없음]**
- 시나리오 4 때문에 작업 하나에 스터디가 여러 개 생기고, `이전 기록`에는 흐름이 많이 섞여 있습니다.
- `carry`, 카드 A, 목록의 `6단계 · 질량 1.21 kg`이 어느 것을 뜻하는지 설계에 없습니다.
- **고침:**
  - 기본은 마지막으로 케이스가 완료된 스터디와 그 흐름입니다.
  - 고른 카드 첫 줄에 `기준: '하중 3 kN' 흐름 (이 작업의 2개 중 최근)`을 보입니다.
  - `이전 기록`은 목록에서 흐름별 줄(`이전 기록 › 브래킷 E2E 설계`)로 나눕니다.
  - 목록 줄에는 모델 파일 이름을 더합니다.

**P5. 프로젝트 `폴더 바꾸기`의 동작이 없습니다. [확인: `sessions.py` `set_local_folder`, `workspace.py` `_find`]**
- 지금은 내 대화의 세션을 모두 끊습니다. "세션을 끝내지 않는다"와 어긋납니다.
- 새 부모 폴더에는 `W01_*`이 없으므로, 찾는 규칙대로면 빈 W01이 새로 생기고 스크립트가 없어집니다 [판단].
- **고침:**
  - `index.json`에 `works: {uid: 절대 경로}`를 둡니다. 찾을 때 이것을 먼저 봅니다.
  - `이전 기록`의 옛 폴더도 여기에 적습니다.
  - 바꾸기는 새 작업부터 적용하고 세션을 끊지 않습니다.
  - 창 문구: `새 작업부터 이 폴더 아래에 만듭니다. 이미 있는 작업 폴더와 AI는 그대로입니다.`

**P6. 이어받기에서 3D 필드와 이미지가 빠집니다. [확인: `service.py`의 h5·fields 경로, `dataset.py` 샘플 경로가 모두 study·case ID 기준]**
- 숫자만 복사하면 새 케이스 ID에 파일이 없어 3D 재학습이 안 됩니다 [판단].
- 옛 `run_by`가 남으면 Output 추가가 "그 PC를 켠 뒤 다시 요청하세요"로 잘못 안내합니다.
- **고침:**
  - 필드·h5·이미지를 서버에서 하드 링크로 복사합니다. 원본 작업을 지워도 남습니다.
  - 복사한 케이스는 `run_dir=None`, `run_by=None`으로 둡니다.
  - Output 추가 안내를 따로 둡니다: `이어받은 {n}건은 원본이 김엔지님 PC에 있어 뽑지 못합니다 → 그 케이스를 다시 돌리세요.`
  - 카드 C에 줄을 더합니다: `받는 것: 스크립트, 설정, 첨부 모델, 완료된 케이스의 숫자·이미지·3D 필드`

**P7. 접합이 모든 새 프로젝트의 기본 경로입니다. [확인: 코드·실험, 보안 프로그램 동작은 미확인]**
- `W01_첫-작업`으로 세션을 띄운 뒤 AI가 첫 답에서 이름을 정하므로, 첫 작업은 항상 접합과 숨긴 실제 폴더로 일합니다.
- 세션은 끝나지 않으므로 이 상태가 계속되고, 접합이 막히면 `첫-작업` 폴더가 계속 남습니다. 14절은 회사 보안 프로그램의 접합 허용 여부를 모른다고 적고 있습니다.
- 실험 (Python 3.12.10): `rglob`, `os.walk`, `copytree`가 모두 접합 안으로 들어가 파일을 두 번 셉니다.
- 그래서 아래 설명은 맞지 않거나 부족합니다.
  - `dds_cae.project_folder`(`d.rglob`)는 `이전 기록`에서 W 폴더까지 두 번 나열합니다. "앞 200개 버그가 사라진다"는 새 작업에서만 맞습니다.
  - 프로젝트 폴더 복사는 파이썬 `copytree`에서 두 배가 됩니다. 탐색기 복사도 같을지는 시험하지 않았습니다.
  - `ALIAS_KEEP = 8`을 작업 폴더에 그대로 쓰면 숨은 옛 이름이 프로젝트 폴더 안에 최대 8개 쌓입니다.
  - `W01_*` 검색은 접합도 찾습니다. `_candidates`처럼 접합을 빼야 합니다.
- **고침:**
  - 관문 G7을 2단계 앞에 둡니다. 회사 PC에서 접합 생성, 탐색기 표시, CAD로 열기, 복사를 시험합니다.
  - `첫 작업`을 없애고 모델 파일 이름이나 요청 앞부분으로 시작합니다. 접합이 막혀도 알아볼 수 있습니다.
  - 작업 폴더의 `ALIAS_KEEP`은 1로 둡니다.
  - 폴더를 훑는 코드는 접합을 건너뛰는 공통 함수를 쓰고, `recipe_bundle`의 `is_symlink` 검사도 바꿉니다.

### 다음 단계 전에 고칠 것

**P8. 숨김 표시를 켠 엔지니어에게 같은 폴더가 둘 보입니다. [확인: `_show_as`가 실제 폴더를 숨김]**
- 숨긴 실제 폴더를 지우면 전부 사라집니다.
- 설계는 안내를 "접합을 못 만들 때만"으로 줄였습니다. 지금의 `_notice`는 이름이 다르면 항상 보입니다.
- **고침:** 이름이 다른 동안 파일 탭에 표시합니다: `숨김 표시를 켜면 옛 이름 폴더도 보입니다. 같은 폴더이니 지우지 마세요.`

**P9. Live Link는 PC 전체에 하나입니다. [확인: `dds_live.py` `NX_QUEUE`, 툴별 고정 포트, `live_launch`는 이미 열린 NX에 그대로 붙음]**
- `spider_m7`이 열린 NX에 W02의 AI가 붙어 옛 모델을 바꿀 수 있습니다 [판단].
- 다른 프로젝트 사이에는 지금도 있는 위험이지만, 이 설계는 같은 부품의 작업을 동시에 살려 두어 더 쉽게 일어납니다.
- **고침:**
  - 값을 바꾸는 호출(`live_set_params`, `live_exec`) 전에 열린 모델 경로를 `DDS_WORK_DIR`과 비교합니다.
  - 밖에 있으면 거절하고 `다른 작업의 모델이 열려 있습니다: … → 새 세션으로 열거나 배치로 진행`을 AI에게 돌려줍니다. 사용자에게 조작을 부탁하지 않습니다.
  - 경로를 못 읽는 툴은 이번에 시험합니다.

**P10. 파일 규칙이 모델과 인클루드를 구분하지 못합니다. [확인: 저장소에 `.asm .mph .nas .dyn` 언급, 목록의 `.k .inp .bdf`]**
- 재료 카드 `mat.k`를 놓으면 `새 모델 mat.k로 보입니다`가 뜹니다.
- `.sldasm`, `.catproduct`, `.asm`, `.nas`, `.dyn`, `.cdb`, `.mph`와 Creo의 `.prt.3`은 걸리지 않습니다. 이 중 `.sldasm`, `.catproduct`, `.cdb`, `.prt.3`은 [판단]입니다.
- **고침:**
  - 확장자는 `catalog.py`에 툴별 `model_exts`로 한 곳에 두고, 대소문자를 무시합니다.
  - 덱 종류는 앞부분을 훑어 노드 정의(`*NODE`, `GRID`)가 있을 때만 모델로 봅니다.

**P11. 관리자와 master에게 막다른 길이 있습니다. [확인: 권한 표, `stalled_view`]**
- 삭제 문구는 `먼저 중지하세요`인데 이들은 중지 권한이 없습니다.
- 주인 PC가 영영 꺼져 있으면 멈춘 케이스 때문에 지울 수 없습니다.
- **고침:**
  - 실제로 돌 때의 주인 외 문구: `박프로님 해석이 돌고 있어 지울 수 없습니다 → 끝난 뒤 지우거나 박프로님에게 중지를 요청하세요`
  - PC가 꺼져 멈춘 케이스는 막지 않고 창에 알립니다: `PC가 꺼져 멈춘 케이스 3건도 함께 지웁니다.`
  - 삭제 뒤 늦게 온 결과는 버립니다.
  - 주인에게 알립니다: `'2차 M9'을 관리자님이 삭제했습니다.`

**P12. `놓는 즉시 카드`는 지금 구조로 불가능합니다. [확인: 해시는 업로드 때 서버가 계산(`sessions.py` `upload_attachment`), 브라우저 해시 코드 없음]**
- 1 GB 파일이면 업로드가 끝날 때까지 `route-check`에 줄 해시가 없습니다.
- 사내 `http://` 주소에서는 브라우저 해시 기능(`crypto.subtle`)이 막힐 가능성이 높습니다 [판단].
- `work_id` 없이 올린 첨부를 정리하는 규칙도 없어 취소한 대용량 파일이 남습니다.
- **고침:**
