# 최적화 문제 정식화 (2026-10-31)

사용자 원문: "최적화 시에 멀티오브젝티브의 문제 정식화에 대해서는 어떻게 처리하고 요청을 하게되어 있나요? 목적함수, 구속조건의 설정을 물어본적이 없습니다."

확인한 사실:
- INSTRUCTIONS 18줄 "없는 것은 기본값을 정해 진행", 13줄 질문은 진행 불가일 때만. 그래서 AI가 목적·구속을 스스로 정할 수 있고 사용자에게 묻거나 보여 주는 절차가 없다.
- Flow 승인 카드에 정식화(목적·구속·변수 범위) 전용 칸이 없다. 스터디를 만드는 값은 AI가 넘긴다.
- objectives는 목록으로 받지만 best_case, publish_convergence, service.suggest는 objectives[0]만 쓴다. 두 번째 목표는 경고 없이 무시된다.
- constraints는 BO에 P(만족)으로 곱해진다. 그러나 doe-surrogate-optimization 스킬은 "제약은 단일 목적 BO만 지원, 페널티로 처리"라고 낡은 내용을 말한다.
- 판단 화면 작업(study-insights)이 다목적 획득(EI 수정 포함)과 파레토를 구현 중이다.

결정(사용자에게 알림, 구현 전):
- 최적화·능동학습을 시작하기 전에 "문제 설정 카드"를 반드시 거친다. DOE만, 표에서 Simulator 만들기, 조회에는 묻지 않는다.
- 카드 내용(쉬운 말): 무엇을 줄이거나 키울까요(목표) / 넘으면 안 되는 조건은요(구속, 값과 단위) / 바꿀 수 있는 값과 범위 / 목표가 둘 이상이면 어떻게 볼까요(균형 후보 보기·파레토 기본, 하나를 목표로 두고 나머지를 구속으로). 출력 목록에서 고르고, AI의 제안을 미리 채운다.
- AI가 구속 값이나 허용치를 지어내지 않는다. 요청이나 자료에 없으면 비워 두고 사용자가 정한다. 제안한 값은 "AI 제안"으로 표시한다.
- 승인된 정식화를 스터디에 저장하고, 승인 뒤 바뀌면 다시 묻는다. 보고서와 판단 화면이 같은 값을 쓴다.
- 받는 값 검증: 없는 출력 이름, 뽑지 않는 출력, 값 없는 구속은 시작을 막고 이유와 할 일을 보인다. 다목적을 조용히 무시하지 않는다.
- 낡은 스킬 문구 수정. 순서: 진입 시나리오와 판단 화면을 합친 뒤.
