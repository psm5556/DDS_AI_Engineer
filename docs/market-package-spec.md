# 마켓 패키지 규격

마켓에 올리는 항목의 형식과 기준입니다. 서버의 검사기(`server/app/market_check.py`)가 이 규칙을 그대로 적용합니다. 규칙을 바꾸면 이 문서와 `server/tests/test_market_check.py`를 함께 고칩니다.

지금 받는 것은 **스킬**(AI에게 주는 작업 방법)뿐입니다. **기능**(MCP, AI가 실행하는 도구)은 실제 AI 도구에서 시험한 뒤 2단계에서 받습니다.

## 1. 사람이 준비할 것

폴더 하나와 `SKILL.md`의 한 줄 설명이면 됩니다. 이름표는 서버가 읽어 만들고, 올린 뒤 등록 화면에서 고칠 수 있습니다.

```text
weld-fatigue/
  SKILL.md            필수. 첫머리에 description 한 줄
  references/         선택. 필요할 때 읽을 문서
  scripts/            선택. AI가 실행할 스크립트
```

스킬 여러 개를 한 항목으로 묶을 때는 이렇게 합니다.

```text
weld-tools/
  plugin.json         선택
  skills/
    weld-fatigue/SKILL.md
    weld-report/SKILL.md
```

시작 틀은 등록 화면에서 받을 수 있습니다(저장소의 `market-templates/`). `skill-text-example`은 지침만 있는 항목, `skill-code-example`은 스크립트가 있는 항목입니다. 이 문서도 등록 화면의 "형식과 기준 전체 보기"로 볼 수 있습니다.

### SKILL.md 첫머리

```markdown
---
name: weld-fatigue
description: 용접부 피로 수명을 평가할 때 쓴다. Abaqus odb의 응력 범위를 S-N 곡선과 비교한다.
---
```

- `description`은 한 줄, 1024자 이내입니다. **언제 쓰는 스킬인지**를 먼저 씁니다. AI는 이 글을 보고 읽을지 정합니다.
- 기본 스킬과 일이 겹치면 어느 쪽을 언제 쓰는지 적습니다. 예: "기본 Abaqus 스킬은 해석 실행, 이 스킬은 피로 평가".
- 첫머리는 서버가 새로 씁니다. `name`·`description`·`license`만 남고 `allowed-tools`·`hooks`·`model` 같은 설정은 빠집니다(등록 화면에 무엇을 뺐는지 보입니다). 이 설정들은 AI 도구의 승인 창을 건너뛰거나 명령을 돌릴 수 있습니다.

### plugin.json (선택)

없어도 됩니다. 있으면 이 값을 먼저 씁니다.

| 값 | 뜻 |
|---|---|
| `name` | 영문 소문자로 시작, 소문자·숫자·하이픈, 40자 이내 |
| `version` | `1.2.0` 형식. 빼면 서버가 올립니다 |
| `displayName` | 화면에 보일 이름. 한글 가능 |
| `description` | 카드에 보일 설명. 100자로 줄입니다 |
| `category` | 후처리·모델링·해석·최적화·보고서·데이터 등 |
| `requiresTools` | 필요한 툴의 id. 예: `["abaqus"]`. 빼면 서버가 이름과 설명에서 어림합니다 |
| `examples` | "이렇게 말해 보세요" 문장, 5개까지 |
| `minAgentVersion` | 필요한 PC Agent 최소 버전 |

## 2. 이름

- 이름은 영문 소문자로 시작하고 소문자·숫자·하이픈만 씁니다. 40자 이내입니다.
- `dds-`, `claude-`, `anthropic-`로 시작하는 이름, 기본 스킬 이름, `con`·`nul`·`com1` 같은 Windows 장치 이름은 쓸 수 없습니다.
- 대문자·밑줄·공백은 서버가 고쳐 줍니다(`Weld_Fatigue` → `weld-fatigue`). 한글 이름뿐이면 `item-<번호>`를 붙이고, 화면 이름은 한글로 둡니다.
- 공개 전에는 사람마다 같은 이름을 쓸 수 있습니다. 남의 비공개 초안이 공개 이름을 막지 않게 하기 위해서입니다. 공개할 때 전체에서 유일한 이름을 잡습니다.
- 묶음 안의 스킬 이름도 공개할 때 봅니다. PC의 프로젝트 폴더에서는 스킬 이름이 경로라 겹치면 한쪽이 밀려나기 때문입니다.

## 3. 검사

올린 코드는 **서버에서 실행하지 않고 디스크에 풀지도 않습니다.** 메모리에서 읽고 Python은 문법 구조(AST)로만 봅니다.

### 받지 않는 것 (거절)

| 항목 | 예 |
|---|---|
| 경로 | 폴더 밖으로 나가는 경로, 절대 경로, 링크 |
| 파일 이름 | 점·공백으로 끝나는 이름, `CON`·`NUL` 등 Windows 예약 이름, `< > " \| ? *` |
| 파일 이름 안의 글자 | 보이지 않는 글자, 방향을 뒤집는 글자 |
| 묶음 | 암호 zip, 압축 폭탄. 압축 20 MB, 파일당 5 MB, 200개, 풀어서 50 MB까지. 웹 화면은 보내기 전에 파일 크기를 봅니다 |
| 실행·컴파일 파일 | `.exe` `.dll` `.pyc` `.pyd` `.so` `.jar` `.lnk` 등 |
| 열면 돌거나 읽을 수 없는 형식 | `.pyz` `.pth` `.egg` `.whl` `.reg` `.msc` `.url` `.inf` `.xll` `.docm` `.xlsm` `.chm`, 압축 파일(`.zip` `.7z` 등) |
| 그림으로 위장 | 내용이 PNG·JPEG 구조가 아닌 `.png`·`.jpg`, 뒤에 다른 데이터나 zip이 붙은 그림 |
| 비밀값 | 개인 키, API 키, 토큰(이 앱의 `dds_` 토큰과 로그인 토큰 포함), 글자 그대로 적은 비밀번호. UTF-16 문서도 봅니다. `.env`, `.pem`, `credentials` 같은 파일 |
| Windows에 풀리지 않는 묶음 | 같은 이름이 파일이면서 폴더, 대소문자만 다른 폴더, 150자가 넘는 경로 |
| 규격 밖 | 점으로 시작하는 파일, `CLAUDE.md`·`AGENTS.md`·`GEMINI.md`, `server/`·`bin/`·`hooks/`, `.mcp.json` |
| Python | 구문 오류(단 Python 2 스크립트는 받고 표시합니다), 파일당 512 KB·항목 전체 2 MB를 넘는 코드, `utf-7`·`unicode_escape`처럼 사람이 읽는 글자와 Python이 읽는 글자를 다르게 만드는 인코딩 선언 |
| AI 도구의 실행 문법 | `SKILL.md`의 `` !`명령` ``과 ` ```! ` 블록(여러 줄, 줄 중간 포함). AI가 읽는 순간 승인 창 없이 돕니다. 다른 문서에 있으면 표시합니다 |
| 규칙 파일 표시 | `DDS Conversa 규칙` 글자. 프로젝트 규칙 파일의 범위를 바꿀 수 있습니다 |
| 문서의 데이터 | `.md`·`.svg` 안의 글자가 아닌 데이터 |
| 설명 | 없거나 1024자를 넘는 설명 |
| 버전 | `1.2.0` 형식(ASCII 숫자)이 아닌 값, 있는 버전 다시 올리기, 있는 버전보다 낮은 버전, 내용이 같은 재등록 |

`.key`는 LS-DYNA 입력 덱 확장자이므로 이름으로 막지 않고 내용만 검사합니다.

`.venv`, `.git`, `__pycache__`, `node_modules`는 빼고 받습니다. 화면과 `scripts/market_publish.py`는 보내기 전에 뺍니다.

### 서버가 고쳐 주는 것

CP949·UTF-16 문서를 UTF-8로, 여러 줄 설명을 한 줄로, `name`을 폴더 이름에 맞게 고치고, 첫머리의 설정을 뺍니다. 이름표(화면 이름·설명·분류·예시)에서 줄바꿈과 보이지 않는 글자를 지웁니다. 무엇을 고쳤는지 등록 화면에 보여 줍니다.

### 검토자에게 표시하는 것

정상일 수도 있는 것들입니다. 공개하려면 검토자가 항목마다 확인해야 합니다. 규칙마다 100곳까지 보여 주고, 더 있으면 전체 수와 함께 잘렸다고 알립니다. 같은 주소는 한 번만 셉니다. `plugin.json`과 등록 양식의 값(이름표)도 같은 검사를 받습니다. 이름표는 AI 안내로 가기 때문입니다.

| 묶음 | 항목 |
|---|---|
| 하는 일 | 다른 프로그램 실행(`from os import system`, `import os as o`, `os.exec*`·`os.spawn*` 포함), 네트워크, `ctypes`·`winreg`, `exec`·`eval`·동적 import·`pickle`, 모듈에 대한 `getattr` |
| 코드 위치 | 플랫폼 내부 코드(`_common`, `agent.dds_agent`), 필요한 툴 내부 모듈, Python 2 문법, 표준 모듈과 같은 이름의 파일, `sitecustomize.py` |
| 검사 불가 | **Python 외 스크립트, 자동 검사가 모르는 확장자, 사람이 읽을 수 없는 파일, `.gif`·`.webp`·`.bmp`.** 자동 검사는 Python만 봅니다. 아는 스크립트만 표시하면 모르는 실행 형식이 지나가므로, 알려진 자료 형식이 아니면 모두 표시합니다 |
| 위장 | 내용이 Python인 문서, `#!`로 시작하는 파일, SVG 안의 스크립트, 문서나 그림을 프로그램으로 실행하라는 문구 |
| AI 지시 | "이전 지시 무시" 같은 문구, 보이지 않는 글자(폭 없는 글자, 변형 선택자, 한글 채움 문자, 제어 문자), 긴 인코딩 문자열, 토큰·설정 파일 언급, 다른 문서의 `` !`명령` `` |
| 외부 | 사내가 아닌 주소(`python.org`·`numpy.org`·`scipy.org`·`w3.org`·`microsoft.com`·`openfoam` 문서는 제외), 원격에서 받아 실행, `pip install`, `npx` |
| 규약 | 없는 `dds-*` 도구 언급, 사용자에게 Live Link 조작 부탁, 끝나지 않게 띄워 두는 프로그램 |
| 기밀 | 절대 경로, `P0012_`·`C0001_doe` 같은 번호, 내 프로젝트 이름, 비슷한 이름의 항목 |

`import`는 거절하지 않습니다. 툴 내장 모듈(`NXOpen`, `odbAccess`)과 플랫폼 모듈(`cae_adapters`)을 쓰는 스킬이 정상이기 때문입니다. 같은 항목 안의 모듈, 표준 모듈, Agent의 직접 의존성에 없으면 "필요한 툴 내부 모듈"로 표시합니다.

### 자동 검사가 못 하는 것

- 특정 조건에서만 나쁘게 동작하는 코드는 지나갑니다.
- 재료 물성, 고객사 모델명, 설계값 같은 기밀은 찾지 못합니다.
- **틀린 공학 판단은 찾지 못합니다.** 코드 없는 스킬도 AI를 움직입니다.

그래서 화면에는 "자동 검사 통과"까지만 쓰고 "안전함"이라고 쓰지 않습니다. 사람이 읽는 단계는 뺄 수 없습니다.

## 4. 종류와 등급

| 종류 | 화면 | 조건 |
|---|---|---|
| `skill_text` | 스킬 | `.md`, 구조를 확인한 `.png`·`.jpg`, 스크립트 없는 `.svg`만 있음. 내용이 코드이거나 그 파일을 실행하라는 문구가 있으면 해당하지 않습니다. 설치 때 확인 창이 없습니다 |
| `skill_code` | 스킬 · 코드 있음 | 그 밖의 모든 경우. 설치 때 "내 PC에서 내 권한으로 실행됩니다"를 확인합니다 |

| 등급 | 보는 사람 | 조건 |
|---|---|---|
| 내 것 · 나만 | 본인 | 거절 검사만 통과 |
| 검토 완료 | 전체 | 관리부서가 내용을 읽고 승인(PIN) |
| 관리부서 제공 | 전체 | 위 조건 + 부서가 유지 책임 |

- 등급은 **버전마다** 붙습니다. 새 버전은 다시 검토합니다.
- 관리자 권한을 받은 사람이 관리부서입니다.
- 코드 있는 항목은 다른 관리자가 승인합니다. 관리자가 한 명뿐이면 기록을 남기고 허용합니다.
- "검토 완료"는 실제 툴에서 돌려 봤다는 뜻이 아닙니다. 시험 기록(`evidence`)이 없으면 화면에 "실제 툴 시험 기록 없음"으로 나옵니다. 있으면 "등록자가 적은 내용이며 관리부서가 확인한 기록이 아닙니다"와 함께 보여 줍니다.

## 5. 버전과 상태

```text
초안 → 나만 쓰기 → 검토 대기 → 공개 → 내림
              ↘      ↗   ↘        ↘ 회수
              검토 대기    반려
```

- 초안은 다시 올리면 바뀝니다. 그래서 나만 쓰기·검토 요청·승인은 사람이 화면에서 본 내용의 지문을 함께 보내고, 그 사이 내용이 바뀌었으면 거절합니다. 없으면 다른 창이나 같은 로그인을 쓰는 스크립트가 사람이 누르기 직전에 내용을 바꿔치기할 수 있습니다.
- 초안을 벗어난 버전은 파일을 고칠 수 없습니다. 이름표(화면 이름·설명·분류·예시)는 파일이 아니므로 새 버전 없이 고칠 수 있습니다. 공개 전에는 만든 사람이, 공개한 뒤에는 관리부서가 PIN으로 고칩니다. 이름표는 AI 안내로 가므로 검토 뒤에 만든 사람이 혼자 바꾸지 못합니다.
- **반려**는 전사 공개만 막습니다. 만든 사람은 그 버전을 계속 쓰고, 고쳐서 다시 요청할 수 있습니다.
- 쓰는 버전은 저장하지 않고 계산합니다. 공개된 가장 높은 버전 중에서, 사용자가 동의한 일 안에 있는 것을 씁니다.
- 새 버전이 더 많은 일을 하면(예: 네트워크 사용) 사용자가 다시 확인할 때까지 이전 버전을 씁니다.
- 코드 있는 항목은 대화가 쓰던 버전을 유지합니다. DOE 도중 버전이 바뀌면 학습 데이터가 섞이기 때문입니다. 스킬 폴더는 프로젝트에 하나뿐이라 같은 프로젝트의 새 대화도 그 버전을 쓰고, AI 안내와 카드에 그렇게 적습니다. 붙드는 대화에 한 시간 동안 요청이 없고 돌고 있는 케이스도 없으면, 또는 사용자가 카드에서 "지금 새 버전으로 바꾸기"를 누르면 새 버전으로 바뀝니다. 지침뿐인 항목은 다음 요청부터 새 버전을 씁니다.
- **내림**은 새 설치만 막습니다. 관리부서가 적은 이유가 카드에 보입니다. **회수**는 쓰지 못하게 합니다.
- 회수할 때 이전 버전으로 돌아갈지 고릅니다. 기본은 돌아가지 않습니다. 고친 버전을 회수했을 때 옛 오류 버전으로 조용히 돌아가면 안 되기 때문입니다.

## 6. 설치

- 설치는 사람만 합니다(웹 로그인 전용 API). AI는 스스로 설치하지 못합니다.
- 설치는 **내 계정의 모든 프로젝트**에 적용됩니다.
- PC가 꺼져 있으면 예약되고, 켜지면 설치됩니다.
- PC Agent가 `~/.dds-agent/market/items/<이름>/<버전>/`에 받습니다. sha256과 파일 목록이 등록본과 정확히 같아야 설치합니다.
- 다음 요청 때 프로젝트의 `.claude/skills`, `.gemini/skills`, `.agents/skills`로 복사하고 프롬프트 끝에 안내를 붙입니다. CLI를 다시 시작하지 않습니다.
- AI가 안내를 보고 쓸 수는 있지만 **반드시 쓰는 것은 아닙니다.**
- 프로젝트에 같은 이름의 사용자 스킬이 있으면 덮어쓰지 않고 그 프로젝트의 대화와 카드에 알립니다. 다른 프로젝트에서는 그대로 씁니다.
- 제거와 회수는 복사본을 지웁니다. **AI가 `scripts/`나 레시피로 복사한 것은 남고, 이미 읽은 내용은 CLI의 기억에 남을 수 있습니다.**
- 회수는 설치했거나 AI가 읽은 적이 있는 사람에게 마켓 메뉴의 숫자와 그 대화의 안내로 사유를 알립니다. 보고서 자료(`market_items_read`)에도 회수된 항목이라고 표시합니다.

## 7. 올리는 길

| 길 | 방법 |
|---|---|
| 웹 | 마켓 > 등록에 폴더나 zip을 놓습니다 |
| 명령줄 | `python scripts/market_publish.py <폴더> --server http://서버:7014 [--private\|--review\|--official]` |
| 나중에 | 대화에서 등록(2단계), 자산화 제출(3단계). 모두 `POST /api/market/submissions` 한 곳으로 들어옵니다 |

자산화 제출은 같은 API에 `source=capture`, `capture_id`, `evidence`를 붙입니다. 자동 공개 경로는 없고 같은 검토 대기열을 지납니다. 등록은 웹 로그인으로만 됩니다(토큰은 403). AI가 초안을 올리는 자산화를 만들 때는 이 길을 넓히지 말고 사람이 확인하는 좁은 길을 따로 둡니다.

## 8. 못 막는 것

- PC에서 도는 항목은 **내 권한을 그대로** 갖습니다. AI CLI 환경에는 토큰을 넣지 않지만 `agent.toml`의 토큰과 브라우저에 남은 로그인(12시간)은 파일이라 읽을 수 있습니다. 토큰으로 `/ws/agent`에 붙으면 실제 Agent를 밀어낼 수도 있습니다. 격리가 아니라 사람의 검토, 고정된 버전, 회수, 기록으로 관리합니다. 그래서 마켓의 승인·반려·내림·회수·스위치, PIN 초기화, 관리자 권한 변경, Agent 배포(새 버전 올리기·최신 지정)는 PIN을 다시 받고, 검토용 계정과 PC에는 코드 항목 설치를 권하지 않습니다.
- "웹 로그인 전용"은 AI의 실수를 막는 장치입니다. 악성 코드까지 막지는 못합니다.
- "검토 없는 코드가 다른 PC로 가지 않는다"는 **마켓 다운로드 경로에 대한 말**입니다. 내 항목을 `scripts/`로 복사해 레시피에 넣으면 멤버 PC로 갈 수 있습니다.
- 서버 전달 내용은 서명하지 않습니다. 서버를 장악하면 Agent 업데이트로도 코드를 보낼 수 있으므로, 서명은 Agent 배포와 함께 넣어야 효과가 있습니다.
- 사내 HTTPS가 없으면 토큰과 sha256이 평문으로 오갑니다.
- 로그인 없이 틀린 PIN을 다섯 번 보내면 그 계정의 **로그인**이 10분 잠깁니다. 이미 로그인한 관리자의 승인·회수는 PIN 재확인 횟수를 따로 세므로 막히지 않습니다. 로그인 자체를 막는 것은 아직 남아 있습니다.
